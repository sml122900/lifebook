# 2026-09-03 — v3 P12 (Chrome prod test18 검증 결과 8건)

## 픽스

- **P12-1 명시적 종료 시 저장 유실** — `handleSend` 의 exit 경로("그만할래요")가 `finishSession` 으로 곧장 빠져 episode 턴을 버렸다(완곡 종료 "그걸로 됐어요"는 `finishEpisodeStage` 로 저장되던 불일치). `finishEpisodeStage` 에서 저장부를 `saveEpisode()` 로 분리해 exit 경로도 본인 발화 ≥1 이면 저장 + `clearPending` 후 종료. 종료 문구는 transcript 에 안 넣음(P10-3 원칙). 저장했으면 마무리 문구에 "이야기는 잘 담아뒀어요" 반영.
- **P12-2 에피소드 대화 중 새 인물 유실** — STAGE4 엔 인물 추출 경로가 없었다. `lib/person-chat.ts` 에 `savePeopleMentionedInEpisode(userId, eventId, question, userText)` 추가 — 본인 발화를 합쳐 기존 추출 프롬프트로 후보를 뽑되 **이름 있는 후보만** 저장(스치는 "친구들"·"어머니" 호칭 과생성 방지). `finishEpisodeChat` 이 Episode 저장 성공 뒤 best-effort 로 호출. 주인공(이미 등록)은 dedup 으로 링크만.
- **P12-3 인물 중복** — `saveOrLinkPerson`: 같은 사용자의 같은 이름(공백 무시, `isDraft=false`, subjectType person) 이 있으면 `createPerson` 대신 `PersonLifeEvent` 링크만 추가. metYear 는 첫 등록값 유지. 이름 없이 관계를 이름 자리에 쓴 경우("친구")는 dedup 제외. `submitPersonAnswer` 도 같은 헬퍼로 통일.
- **P12-4 "김부장님" 파싱** — 추출 프롬프트에 성+직함 결합 호칭 규칙 추가(name "김부장" 통째 + relation "부장"). 이전엔 님도 공백도 없는 "김"/"부장"으로 쪼개져 P11-2 의 "~님 토큰" 규칙이 걸릴 데가 없었다. `buildPersonAddress` 에 `NIM_TITLES`(선생·교수·담임·사장·부장·과장·팀장·선배·원장·목사·신부·사모·소대장·중대장) 추가 — addressed 끝에 "님" 보강("김부장님과"). 선임·고참·사수·가족 호칭은 제외(회귀 케이스 유지). 답변 slice 500→1500(에피소드 합본 입력 대비).
- **P12-5 배우자 호칭** — `SPOUSE_TERMS`(아내·집사람·마누라·와이프·각시 / 남편·바깥양반·신랑·서방). 실명 있으면 "정미숙 씨와", 이름 자리에 호칭이면 "아내분과/남편분과". 요약 프롬프트에 "관계를 이름 앞에(아내 정미숙은)" 규칙 추가.
- **P12-6 카드 href 불일치** — 재현 시나리오 추정: 딥링크(`?gapEventId=중학교&gapType=person`)로 들어온 뒤 채팅 안 갭 칩으로 "결혼 이후"를 시작하면 주소창은 옛 딥링크 그대로 → 새로고침/재진입 시 `initialGap ≠ pending` 이라 엉뚱한 갭이 시작. `init()` 이 initialGap 을 소비한 직후 `history.replaceState("/chat-v3")` 로 주소 정리(서버 왕복 0). `/story-review` 카드 key 도 index → `type:eventId:personId` 로 안정화.
- **P12-7 마무리 멘트 중복** — 모델이 이미 마무리 말로 끝낸 턴(`result.end && !질문형`)에서 `finishEpisodeStage({ afterModelClosing: true })` → 시스템 문구를 "다른 이야기도 있으세요?" 로 축약. 사용자 완곡 종료 경로는 기존 전체 문구 유지.
- **P12-8 갭 카드 3장 미유지** — `pickTopGaps` 확인: 타입별 1장 우선 → 남은 슬롯 우선순위순. 갭이 3개 미만이면 있는 만큼만 노출 = 정상 동작. 코드 변경 없음.
