## 0. 결정(성민, 2026-11-01)과 요약

**결정**

- 기록 방법 2가지: ① 채팅으로 툭툭 대화 → AI 가 노드 생성 제안 ② 지도에서 노드 직접 생성.
- 채팅은 **자유 대화가 주인공**. 골격 질문(출생·학교·군 등)은 처음 한 번 설정 단계로 유지. 이야기가 일단락됐다고 AI 가 판단하거나 일정 턴을 넘기면 "노드로 만들까요?" 제안 카드(제목·시기 중심 노드·인물·장소 미리보기, [만들기][고치기][안 만들기]). 노드를 만든 뒤 대화 맥락 정리(길어짐 방지). 기존 인물 확인(2b-2) 흐름은 이 카드에 흡수.
- 지도: 가운데 줄기(중심 사건) + 왼쪽 이야기·그때의 나 + 오른쪽 **인물록**(모임 = 벤다이어그램 원, 여러 모임 소속은 겹친 칸, 모임 없는 인물은 원 밖) + **장소록**(기본 한 영역, 원하면 장소 묶음 → 같은 벤다이어그램).
- 간선: 이야기 → 인물, 이야기 → 장소. 기본은 선택한 노드의 간선만 + [인물 간선 끄기][장소 간선 끄기] 전체 토글.
- 검색: 1차 글자 검색(제목·본문·인물·장소 이름), 결과를 누르면 지도가 그 노드로 이동·확대. 의미 검색은 4단계.
- 인터뷰 주제 추천: 인생 전체(그래프) 기반, 처리방침 v1.2 이후.
- 전체 보기 상태에서 노드를 누르면 패널 대신 그 노드로 확대 이동.
- 구현 순서: **1 지도 개편**(인물록·장소록·간선·검색·전체 보기 탭) → **2 채팅→노드 제안** → **3 지도 직접 생성**(넣기·빼기·되돌리기·옮기기, 예전 2b-3b 흡수) → **4 인터뷰 주제 추천·의미 검색**.

**요약**

- 지도의 오른쪽 "가지 열"(중심마다 사람·모임·장소)은 없어지고, 사람·장소는 **지도 오른쪽 한곳(인물록·장소록)에 한 번씩만** 놓인다. 이야기와의 관계는 간선으로 보인다(§1).
- 모임은 3개까지 겹치는 둥근 영역(공유 인물이 있을 때만 겹침 — Euler 방식)으로 그리고, 4개 이상이면 고른 3개만 영역으로·나머지는 칩으로 바꿔 본다(§1.3).
- 장소 묶음은 `PlaceGroup`·`PlaceGroupMember` 신설 + `NodeType.PLACE_GROUP`(`PLACE` 바로 위 순위) 추천 — 마이그 1건(추가만), 3단계(§2).
- 채팅: 설정 단계(신상·골격 확인) 뒤에는 자유 대화 하나로 합친다. 한 번의 응답 호출이 "이야기가 일단락됐는지"도 함께 판단하고, 상한은 본인 턴 6. 제안 1회 호출이 지금의 요약 + 인물 추출 2회를 대신한다. 이야기 1편 비용 ≈ $0.04~0.05(Sonnet, 캐시 없음)(§3).
- 검색은 이미 지도로 내려받은 데이터에서 브라우저가 찾는다 — 서버·인덱스 0(§5).

## 1. 지도 레이아웃

### 1.1 영역 배치(세계 좌표 — 배율 1 = CSS px, 고정)

```
 x 40       240   296   420     520                                  
 ┌──────────┐      │  ╭──────╮   ┊  ┌──────── 인물록 ─────────────┐
 │ 이야기    │──────┼──│ 중심  │   ┊  │  (모임 영역 — 벤다이어그램)  │
 │ (왼쪽 열) │      │  ╰──────╯   ┊  │  ╭───────╮╭───────╮         │
 └──────────┘      │             ┊  │  │ 합창부 ╳ 동창회 │         │
 ┌──────────┐      │   ← 간선은 이 ┊  │  ╰───────╯╰───────╯         │
 │ 그때의 나 │──────┼── 통로(420~520)│  모임 없는 분: [ ][ ][ ]     │
 └──────────┘      │   로 지나감  ┊  └────────────────────────────┘
       ...         │             ┊  ┌──────── 장소록 ─────────────┐
                   │             ┊  │  [외가] [부산 해운대] [서울역]│
                   │             ┊  └────────────────────────────┘
```

- **왼쪽·가운데(시간 줄기)는 2b-3a 수정 그대로**: 이야기·그때의 나 열 x 40~240, 줄기 x 296, 중심 노드 x 172~420(248×120 물방울, 전부 같은 크기), 띠 쌓기·접기·10년 표지·겹침 해소(`resolveOverlaps`).
- **오른쪽 가지 열(x 352~552, 중심마다 사람·모임·장소)은 없앤다** — 사람·장소는 인물록·장소록에 한 번씩만. 2b-3a 의 Q38(이야기 안 인물은 가지에서 뺌)은 대상이 없어져 폐기.
- **간선 통로**: x 420~520(중심 노드 오른쪽 끝 420 부터 인물록 520 까지). 이 통로에는 노드를 두지 않는다.
- **인물록**: x 520 부터, 위쪽은 첫 띠 높이(y 32)에 맞춘다(Q51). 제목 줄(22px 굵게, 높이 48) → 모임 영역(§1.3) → "모임 없는 분" 격자.
- **장소록**: 인물록 아래(간격 64). 장소 묶음이 없으면 장소 노드 격자 하나, 있으면 인물록과 같은 영역 그리기(§1.3).
- **노드 크기(고정)**: 인물·장소 노드 168×56(아이콘 + 이름 18px 1줄, 넘치면 말줄임 — 전체 이름은 패널). 격자 간격 12.
- **누가 인물록에 오나**: 사용자의 확정 인물 전부(`subjectType=person`·`isDraft=false`) — 연결이 없는 분(`/people` 에서만 만든 분)도. 확인 대기 초안(2b-2 잔여)은 "모임 없는 분" 끝에 점선 + [문구 필요: 확인 전]. 장소록 = 사용자 `Place` 전부. 이름만 있는 옛 `MemoryPlace`(`placeId` 없음)는 노드가 없어 이야기 안 작은 물방울로만 보인다(백필은 Q72).

**390px·데스크톱**

- 좌표는 화면과 무관(2b-3a 수정의 고정 캔버스). 처음 화면: 390 = 첫 중심 위쪽 가운데·배율 1(지금 그대로 — 인물록은 오른쪽 화면 밖). 데스크톱(지도 영역 폭 ≥ 768) = 배율 1, 줄기가 영역 왼쪽 30% 자리에 오게 → 인물록 앞부분이 함께 보인다.
- **화면 밖 영역 표시(길 잃음 방지)**: 인물록·장소록·줄기가 화면 밖에 있으면 지도 가장자리에 56px 버튼 [문구 필요: 인물록 →]·[문구 필요: 장소록 →]·[문구 필요: ← 시간 줄기]가 뜬다. 누르면 그 영역 전체가 화면에 들어오게 이동·확대(`zoomToElement`, 배율 상한 1 — 글씨가 커지기만 하지 작아져 읽을 수 없게 되진 않게, 영역이 크면 영역 위쪽에 맞춤). 머리·도구줄 자리는 늘리지 않는다(390 지도 높이 보존).

### 1.2 겹침 방지

- 시간 줄기 쪽은 지금처럼 쌓기로 구성상 0 + `resolveOverlaps`.
- 인물록·장소록은 x 520 오른쪽에서만 놓이므로 시간 줄기 쪽(x ≤ 420)과 가로로 겹칠 수 없다. 안쪽은 칸(cell) 격자라 구성상 0(§1.3). 마지막에 지도 전체 노드에 `findOverlaps` → `resolveOverlaps` 를 한 번 더 건다(지금과 같은 안전망 — 정상 배치 해소 0회를 회귀가 확인).
- 모임 영역(둥근 도형)은 노드가 아니라 배경 그림이라 겹침 검사 대상이 아니다. 대신 "각 칸은 그 칸의 모임 도형 안에만 들어 있고 다른 모임 도형 밖에 있다"를 회귀가 확인(§1.3).

### 1.3 벤다이어그램(모임 영역) 배치 알고리즘

모양은 원 대신 **큰 라운딩 사각**(모서리 반지름 r = 짧은 변의 40% 와 안쪽 여백 p 의 3배 중 작은 값 — 구석 칸의 모서리가 둥근 곳 밖으로 나가지 않으려면 p ≥ 0.3r). 원·타원은 칸 사각형을 감싸려면 지름이 √2 배 커져 이웃 칸(다른 모임 전용 칸)까지 덮어 소속을 잘못 보이게 한다. 둥근 사각은 칸 묶음을 정확히 감싸면서 벤다이어그램처럼 보인다. 디자인 시스템의 물방울 예외(My Life 한정)와 같은 결.

1. **소속 신호**: 인물마다 속한 모임 집합(비트). 같은 집합끼리 한 **칸**에 모은다. 칸 안 배치 = 인물 노드 격자(4명 이하 1열, 그 이상 2열), 이름 가나다순. 도형 안쪽 여백 p = 24(→ r ≤ 80).
2. **겹침은 공유 인물이 있을 때만**(Euler 방식 — Q53). 교집합 칸이 비면 그 칸은 폭 0 → 두 도형이 붙어 있되 겹치지 않는다. 어르신에게 "빈 겹침"은 뜻이 없다.
3. **모임 1~3개 — 칸 틀(템플릿)**:

```
모임 1개        모임 2개                     모임 3개
╭───────╮      ╭───────────╮                ╭──────A───────╮
│   A   │      │ A만 │ A∩B │ B만 │          │ A만 │ A∩B │ B만 │ ← B 는 위 오른쪽 2×2
╰───────╯      ╰─────A─────╯                │ A∩C │ ABC │ B∩C │ ← C 는 가운데 줄 3칸
                     ╰─────B─────╯           ╰───────────╯         + 아래 C만
                                                        │ C만 │
```

   - 2개: 칸 순서 [A만][A∩B][B만] 가로. 도형 A = 앞 두 칸, B = 뒤 두 칸.
   - 3개: 3×3 격자의 7칸 — 윗줄 [A만][A∩B][B만], 가운데 [A∩C][ABC][B∩C], 아랫줄 가운데 [C만]. 도형 A = 위 왼쪽 2×2, B = 위 오른쪽 2×2, C = 가운데 줄 전체 + 아래 가운데. 각 도형이 감싸는 칸은 전부 그 모임을 포함한다(검증 완료 — 모든 칸이 정확히 자기 집합의 도형 안).
   - 같은 열·줄의 칸 폭·높이는 그 열·줄의 가장 큰 칸에 맞춘다(격자 정렬). 빈 칸은 0.
   - 칸 사이 간격 g ≥ 2p + 8 = 56 — 한 도형의 안쪽 여백이 그 모임에 속하지 않은 이웃 칸에 닿지 않게.
4. **모임 4개 이상 — 대안 비교**(Q52):

| 안 | 모양 | 장단 |
|---|---|---|
| **① 고른 3개만 영역(추천)** | 영역 위에 모임 칩 줄 [합창부 ✓][동창회 ✓][교회 ✓][등산회] — 영역에 보일 모임 3개를 고른다(기본 = 인원 많은 3개). 안 보이는 모임에만 속한 분은 "모임 없는 분" 격자에 꼬리표 [문구 필요: 다른 모임 N] | 언제나 3개 이하라 읽기 쉽다. 전체를 한눈에 못 보는 대신 칩으로 바꿔 본다 |
| ② 사각 격자(카르노 맵식) | 4개 = 4×4, 5개 = 4×8 칸, 모임마다 가로·세로 띠 | 모든 교집합 표현 가능, 그러나 어르신에게 읽기 어렵다 |
| ③ 모임별 띠 + 소속 꼬리표 | 모임마다 가로 띠, 여러 모임 분은 첫 모임 띠에 두고 꼬리표 | 단순하지만 "겹침"이 안 보인다 |

5. **모임 없는 분**: 모임 영역 아래 격자(3열), 가나다순.
6. **장소록**도 같은 알고리즘(장소 묶음 = `PlaceGroup`, §2). 묶음이 없으면 5 의 격자만.
7. 회귀(1단계 `test-my-life` 추가): 모임 0·1·2·3·4·5개 × 칸 분포 무작위 합성 데이터에서 — 노드 교차 0, 각 노드가 자기 집합 도형 안·다른 도형 밖, 같은 입력 같은 출력.

### 1.4 간선 경로 — 곡선, 줄기 노드 회피

- 이야기 → 인물: 시작 S = 이야기 노드 오른쪽 끝(꼭지 높이), ① S 에서 **수평으로 통로(x 440)까지** — 이야기 노드의 y 범위는 자기 띠의 가지 영역이라 그 높이에 중심 노드·펼치기 버튼·10년 표지가 없다(띠 쌓기 구성상). 그래서 줄기를 가로질러도 중심 노드를 지나지 않는다. ② 통로 점 T 에서 인물 노드 왼쪽 가운데 E 까지 3차 베지어, 제어점 (T.x+Δ, T.y)·(E.x−Δ, E.y), Δ = clamp(|E.y−T.y|/3, 40, 160). 제어점 x 가 T.x~E.x 사이라 곡선의 x 는 단조 — 통로에서 인물록으로만 간다.
- 그때의 나 → 인물(관계 대상)·이야기 → 장소: 같은 경로(장소는 장소록 노드로).
- 중심 → 인물(`PersonLifeEvent`)·중심 → 장소(`NodeLink`): 중심을 선택했을 때만 그린다(Q55). 시작 = 중심 노드 오른쪽 끝(x 420).
- 이야기 노드 안 작은 물방울(인물·장소 이름)은 유지한다(Q56) — 간선은 기본으로 숨겨 두므로, 이름은 물방울로 바로 읽힌다.
- 간선은 노드 뒤 SVG 한 장(`aria-hidden`) — 인물록 안쪽으로 들어갈 때 다른 인물 노드 뒤로 지나간다(노드가 위에 그려짐).
- 회귀: 간선 곡선의 표본점(20점)이 어떤 중심 노드 사각형 안에도 없음.

### 1.5 선택 간선 강조

- **기본 = 선택한 노드의 간선만**. 노드를 누르면 선택 + 패널. 선택은 패널을 닫아도 남고, 머리 줄의 "지금 보는 곳" 자리가 [문구 필요: 선택 — 김민수 · 이야기 4개] + [문구 필요: 선택 풀기](56px)로 바뀐다. 빈 곳 탭·[선택 풀기]·Esc 로 해제.
- 선택 노드: 테두리 4px `ink`. 연결된 노드: 바깥 윤곽 3px `action`(간격 3px) — 키보드 포커스 링(`brand` 4px)과 색·두께를 다르게. 나머지는 흐리게 하지 않는다(투명도는 글자 대비를 떨어뜨림, 2b.1 판단 유지). 간선: 인물 = 3px `emerald-700` 실선, 장소 = 3px `sky-700` 긴 점선(8·6) — 색 + 선 모양 두 가지로 구분(Q59).
- 패널은 지도 화면에서 반 높이(최대 50dvh)로 — 위쪽 절반에서 간선이 보인다. 패널에 [문구 필요: 연결된 곳 모두 보기] → 선택 노드 + 연결 노드 전체가 들어오게 `zoomToElement([노드들])`(라이브러리가 여러 대상 지원).
- **[문구 필요: 인물 간선 끄기]·[문구 필요: 장소 간선 끄기]**: 머리 줄 메뉴(Q57 — "전체 간선 켜기"는 두지 않음, 노드 100개면 선이 수백 개). 끄면 선택해도 그 종류 간선은 안 그린다. 상태는 같은 탭 안 기억(`sessionStorage`).

### 1.6 전체 보기 상태 탭 = 확대

- 배율 < 0.6(18px 글씨가 화면에서 11px 미만 — Q60)에서 노드를 누르면(탭·Enter 둘 다) 패널 대신 그 노드를 화면 가운데·배율 1 로(`zoomToElement`, 200ms). 다음 누름부터 패널.
- 터치 보정: 작은 배율에선 Chrome 이 빈 곳 탭을 가까운 노드로 옮긴다(2b-3a 수정 실측) — 이 규칙 덕에 잘못 열린 패널 대신 확대가 되어 오히려 자연스럽다.

### 1.7 접근성 — 목록 보기의 인물록·장소록

- 지도 DOM 순서: 시간 줄기 목록(지금 그대로) → `<section aria-labelledby>` 인물록 → 장소록. 모임 도형·간선은 `aria-hidden`.
- 인물록은 칸마다 `<ul>` + 칸 이름(보이는 글자): [문구 필요: 합창부만]·[문구 필요: 합창부와 동창회 둘 다]·[문구 필요: 모임 없는 분]. 인물 버튼 이름 = "사람, 김민수, 이야기 4" (연결 수 포함).
- **목록 보기(`?view=list`)**: 시기 순 목록 다음에 "인물록" 절 — 모임별 묶음(여러 모임인 분은 그 모임들 각각에 나오고 꼬리표 [문구 필요: 여러 모임 — 합창부·동창회]), "모임 없는 분" 묶음. "장소록" 절 같은 방식. 인물을 누르면 같은 패널(나온 이야기 목록 = 간선의 글자 대체).
- 간선의 글자 대체: 패널의 "나온 이야기"(인물·장소)·"함께 나온 분·나온 곳"(이야기) 목록. 각 항목 누르기 = 지도에서 그 노드로 이동·선택.
- 화면 밖 영역 버튼·[찾기]·간선 토글 = 56px·18px. 키보드: Tab 순서 = 시간 줄기 → 인물록 → 장소록(문서 순서), 화살표 이동·`+`/`-`/`0` 은 지금처럼.

### 1.8 데이터(1단계)

- `getMyLifeData` 확장: 확정 인물 전부·인물 모임(+구성원)·사용자 `Place` 전부(+3단계 장소 묶음). Prisma 호출 수 고정 유지(지금 6 → 7~8, 기록 양과 무관).
- 연결 목록은 노드별로 미리 묶어 클라이언트에 넘긴다(선택 시 간선 계산은 클라이언트 — 서버 왕복 0).

## 3. 채팅 → 노드 제안(2단계)

### 3.1 자유 대화 진입 구조 — `/chat-v3` 재편 범위

| 지금 단계(stage) | 개편 후 |
|---|---|
| `profile_year`·`profile_region`(신상) | **설정 단계** — 그대로 |
| `confirm`(골격 확인질문 + 확인마다 이어지는 이야기·인물 질문) | **설정 단계** — 골격 확인만(Q65 추천: 확인 뒤 사건별 이야기·인물 질문은 빼고, 갭 칩으로 돌린다 — 설정을 짧게) |
| `episode`(대상 사건 이야기, 후속 2회 상한, 마무리 = 요약 + 인물 추출) | **자유 대화로 흡수** — 대상 사건은 "주제 힌트"로만 남는다(제안 카드의 시기 기본값) |
| `person`(그 시절 가까이 지낸 분) | **자유 대화로 흡수** — 주제 힌트 = 인물 |
| `open`(자유 발화 한 턴 분류 → 이야기면 **즉시 CUSTOM 중심 생성** + episode 단계) | **자유 대화(주인공)** — 중심은 [만들기] 때만 생긴다(즉시 생성 폐기) |

- 진입: 설정이 끝났으면(골격 생성 + 미확정 필수 0 — 지금 `/enter` 판정과 같음) 곧바로 자유 대화. 딥링크 `?gapEventId=…&gapType=episode|period|person|person_episode` 는 자유 대화 + 주제 힌트로 바뀐다(My Life 패널 [이야기 추가]도 같은 링크). 첫 AI 말은 주제 힌트가 있으면 기존 오프닝 템플릿(`lib/episode-opening.ts`), 없으면 [문구 필요: 자유 대화 첫 인사].
- 갭 칩(지금 `open` 단계 위 3개)은 유지 — 자유 대화의 "이런 이야기는 어떠세요" 시작점.
- 바뀌는 코드(2단계 착수 때 확정): `ChatV3Client` stage 축소, `respondToOpenChat`/`promoteOpenTurn`(즉시 승격) 퇴역, `continueEpisodeChatCore` 의 후속 질문 생성은 자유 대화 응답으로 일반화, `finishEpisodeChatCore` 의 요약·인물 추출은 제안(§3.3)으로 대체 — 저장은 `createEpisodeBridge` 를 그대로 쓴다. 대기 대화(`ChatV3PendingContext` — EPISODE/PERSON, 대상 사건 필수)는 구간 기억(§3.5)으로 대체.
- 범위 밖: `/onboarding-episode-chat`(V2 STAGE4)·말동무(`/life-timeline/companion`, V2) 무변.

### 3.2 제안 시점 판정

- **같은 호출에서 판단**: 자유 대화 응답 호출 1회가 JSON `{ reply, segment: "continue" | "done" | "topic_shift" }` 를 돌려준다(지금 `promoteOpenTurn` 이 분류 + 응답을 한 호출로 받는 방식과 같다 — 호출 2회는 어르신 체감 지연).
  - `done`: 이야기가 일단락(AI 가 같은 주제로 후속 질문을 2번 했고 답이 짧아짐, 또는 본인이 마무리 말).
  - `topic_shift`: 방금 턴이 새 이야기를 시작함 → **직전 턴까지**로 제안을 만들고, 방금 턴은 새 구간의 첫 턴.
- **코드 상한·하한**(AI 판단과 무관하게):
  - 상한: 구간 본인 턴 **6**(Q64) — 6턴째 응답 뒤 제안. 운영 실측 이야기당 본인 턴 평균 2.1·최대 3, 본인 메시지 평균 18자라 6턴이면 넉넉하다.
  - 하한: 실질 본인 발화 2턴 미만이면 `done` 이어도 제안 안 함(인사·맞장구로 카드가 뜨지 않게) — 단 마무리 말(`matchClosing`)로 끝내면 1턴이어도 제안.
  - 명시적 종료("그만할래요" 등 `matchClosing` exit): 내용이 있으면 제안 후 대화 종료.
- 사용자가 직접: 입력창 옆 [문구 필요: 지금 이야기 남기기](56px, 내용 1턴 이상일 때) — AI 판단을 기다리지 않고 제안.

### 3.3 제안 카드 — 데이터·저장 경로

**제안 호출 1회(Sonnet 고정 — 추출 정책과 같음)**: 입력 = 구간 대화 + 후보 목록(사용자의 확정 중심 id·이름·연도, 확정 인물 id·이름·관계, 장소 id·이름 — 메모·본문 제외, Q70) + 주제 힌트. 출력 JSON:

```
{ title, summary,                      // summary = Episode 본문(지금 요약 규칙·NO_CONTENT 그대로)
  center: { matchId } | { new: { label, year } },
  people: [{ name, relation, matchId? }], places: [{ name, matchId? }],
  kind: "STORY" | "SELF" }
```

- 코드 검증: `matchId` 는 그 사용자 것만(아니면 버리고 이름 매칭 — `findCompatiblePerson`), 연도 범위, 이름 길이(50/30), 지금 요약 프롬프트의 2차 방어(맞장구·인물 머리줄만으로 문장 금지) 그대로.
- **카드**(대화창 안, 대화는 계속 가능):

```
┌ [문구 필요: 노드로 만들까요?] ────────────────┐
│ 제목  수학여행 가던 날                         │
│ 시기  ◉ 1974 고등학교 입학   (새 시기면 "새로") │
│ 사람  김민수(이미 계신 분) · 박영수(새로)       │
│ 장소  경주(새로)                              │
│ 본문  고등학교 때 수학여행으로 경주에 갔다…      │
│ [만들기](primary) [고치기] [안 만들기]          │
└──────────────────────────────────────────────┘
```

- **[만들기]**(트랜잭션 + 실패 시 이야기 우선 — 지금 "이야기 본문이 먼저, 정리는 best-effort" 원칙):
  1. 중심: `matchId` 또는 새 CUSTOM(`createCustomLifeEvent` — 연도 순 자리).
  2. 이야기: `createEpisodeBridge`(본문 = summary, rawTranscript = 구간 대화, kind).
  3. 사람: 있는 분 → `saveNodeLink(EPISODE→PERSON, CONFIRMED)`, 새 분 → `createPerson` 후 같은 연결. 중심 연결은 지금 [맞아요]와 같게 `PersonLifeEvent`(`saveNodeLink` 입구 — LIFE_EVENT>PERSON). 만난 해 = 시기 불일치 규칙(Q33 — 출생 중심 + 비가족이면 비움).
  4. 장소: 있는 곳 → `saveNodeLink(EPISODE→PLACE)`(MemoryPlace 로 넘김), 새 곳 → `Place` 찾기-또는-만들기(같은 이름·주소면 재사용) 후 같은 연결.
  5. 확인된 연결은 전부 CONFIRMED — **초안(isDraft) + PROPOSED 를 만들지 않는다**(사람이 카드에서 이미 확인). 2b-2 의 `savePeopleMentionedInEpisode` 는 자유 대화에서 호출하지 않는다.
- **[고치기]**: 같은 카드가 입력 단계로 — 제목·본문(VoiceTextarea), 시기(확정 중심 목록에서 고르기 + [새 시기]), 사람·장소마다 [빼기]·이름 고치기·[추가]. **같은 이름 확정 인물 되묻기**(2b-2 후속 규칙 — 이름만 같아도 [같은 분이에요]/[다른 분이에요])를 그대로 이 카드 행에서.
- **[안 만들기]**: 아무것도 저장 안 함(대화 로그에는 남음). 같은 구간으로 다시 제안하지 않는다.
- 카드가 2b-2 의 대화창 확인 카드(Q25 갱신)·`/story-review/confirm` 신규 유입을 대신한다(§6).

### 3.4 맥락 정리

- 대화 로그(`OnboardingChatMessage`)는 지금처럼 전부 저장·표시(최근 N개 복원).
- **모델에 보내는 맥락**은 "현재 구간 대화 + 방금 만든 노드 한 줄 요약 최대 2개"([문구 필요 아님 — 시스템 입력] "방금 '수학여행 가던 날' 이야기를 남겼어요")만. 노드를 만들거나 [안 만들기] 하면 구간이 새로 시작된다. 그래서 응답 호출 입력은 구간 상한(본인 6턴 + AI 6턴 ≈ 0.5k 토큰) 안에서 일정하다.

### 3.5 구간 기억(재진입)

- 새 테이블 `ChatV3Segment`(사용자당 1행 — 지금 `ChatV3PendingContext` 의 싱글턴 방식): `userId @unique Cascade` · `startedAt`(구간 시작 = 이 시각 이후 로그가 구간) · `userTurns` · `topicEventId?` · `topicPersonId?` · `proposal Json?`(만들었으나 아직 결정 안 한 카드 — 새로고침에도 카드 유지) · `updatedAt`. 마이그 추가만 1건(2단계).
- 재진입: 구간이 있으면 [문구 필요: 아까 하시던 이야기 이어가기 안내] — 카드가 있으면 카드부터.
- 오래된 구간(Q66): 마지막 활동 7일이 지나면 재진입 때 바로 제안 카드("남길까요?")로 마무리 권유.
- `ChatV3PendingContext` 는 2단계에서 읽기만 남기고(진행 중 대기 대화 마무리), 비면 다음 정리 때 테이블 삭제 검토.

### 3.6 골격 설정 단계와의 경계

- 설정 = 신상(출생 연도·지역) + 골격 확인질문. 끝 판정은 지금 `/enter` 와 같다(골격 생성 + 미확정 0). 끝나면 자유 대화.
- 설정 중 사용자가 이야기를 꺼내면(지금은 확인 뒤 이야기 단계로 감): 확인 답은 그대로 처리하고, 내용은 구간 첫 턴으로 넘긴다(설정이 끝난 뒤 첫 제안 카드에 포함).
- 설정 뒤 남은 선택 골격(대학·군 등 UNCONFIRMED 선택 항목)은 갭 칩·My Life 에서 나중에.

### 3.7 비용 추정(Sonnet $3/$15 per MTok, 캐시 없음 기준)

| 호출 | 입력 | 출력 | 1회 |

| 자유 대화 응답 + 구간 판정 | 시스템 1.5k + 구간 ≤0.5k + 최근 노드 0.1k ≈ 2.1k | ≈ 0.12k | ≈ $0.008 |

- 비교: 지금 `/chat-v3` 자유 대화 경로 = 턴마다 분류 1 + 후속 ≤2 + 요약 1 + 인물 추출 1 ≈ 5회, 인터뷰 이야기 실측 1건 3회 $0.011(짧은 답). 새 방식은 "요약 + 추출 2회 → 제안 1회"로 줄고, 턴 응답이 구간 판정을 함께 한다.

- 차감(Q63): 도그푸딩 동안 무료 + `trackAiUsage` 로 실측 기록.

### 3.8 오늘의 인터뷰와의 관계

- 인터뷰는 남긴다 — "하루 6문항"의 안내형 대화(자유 대화의 짝).

## 4. 지도 직접 생성(3단계)

### 4.1 진입

- 머리 줄 [문구 필요: + 만들기](56px) → 종류 고르기 시트: 시기(중심) · 이야기 · 그때의 나 · 사람 · 장소 · 모임 · 장소 묶음(Q71 — 오른쪽 아래 비서 버튼과 겹치지 않게 머리 줄).
- 맥락 진입: 중심 패널 [이야기 추가] → [말로 이야기하기](자유 대화 + 주제 힌트) / [문구 필요: 직접 쓰기]; 인물록 제목 옆 [+ 사람]·[+ 모임]; 장소록 제목 옆 [+ 장소]·[+ 묶음].
- 만든 뒤: 지도가 새 노드로 이동·확대, 선택 상태(간선 보임), 패널에 [되돌리기](다음 동작 전까지).

### 4.2 종류별 생성 흐름(기존 함수 재사용, 연결은 `saveNodeLink` 입구만)

| 종류 | 입력 | 저장 |
|---|---|---|
| 시기(중심) | 이름(30) · 연도(선택) · 끝 연도(선택) | `createCustomLifeEvent`(연도 순 자리, 연도 없으면 맨 뒤) + `endYear` |
| 이야기 | 시기 고르기(맥락 진입이면 고정) · 본문(VoiceTextarea) · 사람·장소 넣기(선택) | `createEpisodeBridge`(kind STORY) + 연결 |
| 그때의 나 | 시기 · 누구와(사람·모임 고르기 또는 범주 글자) · 본문 | `createEpisodeBridge`(kind SELF) + `EPISODE→PERSON`·`EPISODE→PERSON_GROUP` |
| 사람 | 이름(50) · 관계(30) · 모임(선택) | `createPerson` — 같은 이름 확정 인물 되묻기(2b-2 후속 규칙) |
| 장소 | `PlaceSearchInput`(네이버/구글) 또는 이름만 | `Place` 찾기-또는-만들기(같은 이름·주소 재사용) |
| 모임 | 이름 · 구성원 고르기 | `PersonGroup` + `saveNodeLink(PERSON_GROUP, PERSON)` → `PersonGroupMember`(입구로 넘김 — §2) |
| 장소 묶음 | 이름 · 장소 고르기 | `PlaceGroup` + `saveNodeLink(PLACE_GROUP, PLACE)` → `PlaceGroupMember` |

### 4.3 넣기·빼기·되돌리기·옮기기(Q34·Q50 통합)

- **넣기**: 노드 패널의 [인물 넣기]·[장소 넣기]·[모임에 넣기]·[묶음에 넣기] — 기존 목록 고르기 + 새로 만들기(`node-graph-self.md` §6 2b.1 의 5 넣기 표 그대로, 저장은 전부 `saveNodeLink`).
- **되돌리기**: 넣은 직후 같은 패널 [문구 필요: 되돌리기] — 방금 결과(`store`·`linkId`)를 `removeNodeLink` 로. 다음 동작이 있으면 사라진다.
- **빼기**: 패널의 연결 노드 행마다 [빼기] → 패널 안 확인 단계(브라우저 확인창 아님) [문구 필요: 빼기 확인] → `removeNodeLink`. **연결만 끊는다**(노드 삭제 아님).
- **`removeNodeLink`(신설, 입구 하나)**: `saveNodeLink` 와 같은 방향 정규화·양 끝 소유 확인 → 쌍에 따라 `NodeLink` 행 삭제 / `PersonLifeEvent` 삭제 / `MemoryPlace`(그 이야기 브릿지의 그 `placeId` 행) 삭제 / `PersonGroupMember`·`PlaceGroupMember` 삭제. 주 소속(`Episode.lifeEventId`)·대상 인물(`Episode.personId`)은 빼기 대상이 아니다(옮기기·인물 고치기로).
- **옮기기**(Q34): 이야기 패널 [다른 시절로 옮기기] — `moveEpisodeToLifeEvent`(2b.1 의 5 설계 그대로 — 주 소속·브릿지 연도/제목·`hasEpisode` 두 곳·추가 소속 정리·`PersonLifeEvent`·만난 해 규칙 3).
- **노드 삭제**: 이야기는 기존 지우기(`deleteEpisode`, 가족 반응 경고 포함), 직접 추가 중심은 `deleteCustomLifeEvent`, 사람은 `/people` 기존 삭제, 장소·모임·묶음은 새 삭제(트리거·FK 가 연결 정리). 패널 맨 아래 tertiary [문구 필요: 이 노드 지우기] + 확인 단계.
- 이야기 본문 고치기·블로그 편집(2b-3c/2b-4)은 이 단계 뒤(본문 고치기는 기존 평문 고치기를 패널에 연결하는 데까지).

## 5. 검색(1단계)

- **대상 필드**: 중심 이름(`label`·`correctedLabel`)·이야기 본문(`Episode.content` — 지도 데이터에 이미 있음)·인물 이름·관계·장소 이름·주소·모임/묶음 이름.
- **인덱스 없음 — 브라우저에서**: 지도 데이터가 이미 사용자 전체 노드를 내려받는다(운영 최대 노드 36, 이야기 본문 평균 67자). 질의마다 메모리에서 거른다(입력 멈춘 뒤 150ms). 서버 왕복·DB 인덱스 0. 노드가 수천 개가 되면(지도 성능 상한과 함께) 서버 검색 + `pg_trgm` 인덱스로 옮긴다.
- **맞추기 규칙**: 양쪽 NFC 정규화 + 소문자 + 공백 제거 후 부분 일치("김 민수" = "김민수"). 초성 검색("ㄱㅁㅅ")은 1차 제외(Q61).
- **결과 화면**: 머리 줄 [문구 필요: 찾기](56px) → 반 높이 시트, 입력칸 56px·18px(음성 입력 버튼 — VoiceTextarea 방식). 결과 행(56px 이상): 종류 꼬리표 · 이름(또는 본문 앞뒤 20자에 일치 부분 굵게) · 시기. 최대 30개, 순서 = 이름 일치 > 본문 일치, 같은 순위는 시기 순. 결과 0 → [문구 필요: 찾는 기록이 없어요].
- **결과 누르기**: 시트 닫힘 → 그 노드가 접힌 띠 안이면 그 띠를 펼침 → `zoomToElement(노드, 배율 max(지금, 1), 300ms)` → 선택(간선 표시) + 포커스. 두 시기에 걸친 이야기는 주 소속 쪽. 패널은 열지 않는다(한 번 더 누르면 패널).
- 목록 보기에서도 같은 [찾기] — 결과 누르기 = 그 항목으로 스크롤·포커스.
- 의미 검색(4단계): 기억 카드 임베딩(Voyage)·처리방침 v1.2 이후(`node-graph-self.md` §5 Q14).

### 8.2 설계와 달라진 것

- **[연결된 곳 모두 보기] → [연결된 곳 차례로 보기(N)]**: 선택 노드 + 연결 노드 전체를 한 화면에 맞추면(`zoomToElement([노드들])`) 이야기 열과 인물록이 멀어 배율이 0.09 까지 떨어져 글씨를 못 읽었다(실측). 누를 때마다 선택 노드 → 연결 노드를 지도 순서대로 하나씩, 배율 1 이상으로 옮긴다. 연결 노드가 화면 밖에 있을 때 가장자리 버튼으로 뜬다.
- **인물·장소 노드 폭 184**(설계 168): 아이콘 + 18px 이름 + 다른 모임 꼬리표("+1")가 들어가게.
- **모임 이름 = 누를 수 있는 노드**(`gl:`): 누르면 그 모임 패널(구성원 목록 → 누르면 그분으로 이동), 선택하면 구성원이 "연결된 곳" 윤곽. 모임 4개 이상의 칩(`gc:`)은 눌러서 영역에 보일 모임을 바꾼다(새로 고른 모임이 앞에 붙고 넷째가 빠짐 — 기본 상태에선 인원이 가장 적은 것).
- **"지금 보는 곳"**: 화면 가운데가 인물록·장소록이면 "지금 보는 곳: 인물록/장소록"(설계엔 없음 — 실측에서 인물록을 보는데 "1957 국민학교 입학"이 떠 있었다).
- **겹침 해소 안전망은 시간 줄기에만**: 인물록·장소록은 칸 격자라 구성상 겹치지 않고, 해소가 칸을 밀면 도형 소속이 깨진다. 지도 전체 겹침 0 은 회귀가 확인(정상 배치 해소 0회).

- **데스크톱 처음 화면**: 배율 1, 줄기가 지도 영역 왼쪽 30% 자리(설계대로) — 인물록 앞부분이 함께 보인다. 390 은 줄기 가운데.

### 9.3 규칙(설계와 달라진 것 포함)

### 10.3 응답 말투("-습니다")

- 재현 픽스처(미커밋, 실제 Haiku): 2단계 실측에서 "잘 들었습니다"가 나온 군대 이야기 4턴 × 10회 = 40응답. 조건 A(원래 대화)·A + 방금 남긴 이야기 제목·B(본인이 "-습니다"체로 말함).
- 고치기 전: A 0/40 · A+제목 0/40 · B 0/40 — 재현되지 않음(앞선 발생은 실제 모델 시험 2회 중 1회의 마무리 응답 1건).
- 프롬프트: 규칙에 "본인이 '-습니다'체로 말해도 대화체로(잘못: 잘 들었습니다·감사합니다 / 바르게: 잘 들었어요·고마워요)" + 예시 대화 3개(이어가기·"-습니다"체 본인에게 대화체로·일단락).
- 고친 뒤: A 0/40 · B 0/40.
- 예시를 넣으며 생긴 문제와 처리: 처음 예시가 재현 대화와 내용이 겹쳐 모델이 예시 답을 베끼며 JSON 없이 문장만 냄(80회 중 3회 → 기본 문구로 대체). 예시를 다른 이야기로 바꾸고 형식을 "당신: {JSON}"으로 → 0/40 · 0/80. 코드도 JSON 없이 문장만 오면 기본 문구 대신 그 문장을 답으로(판단은 continue).

### 12.1 [만들기] 뒤 다음 제안에 저장한 이야기가 다시 들어가던 것

- 원인: 구간 경계는 맞았다(`startedAt` = 카드1 `until`). 새 구간 안에 화면이 남긴 안내문("'…' 이야기를 My Life 에 남겼어요.")이 대화 로그로 들어가 제안 입력 [대화]에 섞였고, AI 응답도 앞 이야기를 언급해 Sonnet 이 요약에 다시 썼다.
- 고침: ① 앱 안내문(인사·설정 끝·재진입·예산·카드 먼저·반영했어요·만든 뒤·안 만들기 등 `lib/free-chat-copy.ts` 문구)은 구간 대화에서 뺀다(`isAppNotice`). `ChatV3Client` 가 직접 쓰던 안내 두 줄도 copy 로 옮김. 경계(`until`)는 안내문까지 포함한 마지막 메시지 바로 뒤. ② 제안 입력에 `[방금 남긴 이야기 — 다시 쓰지 마세요]`(방금 만든 이야기 최대 2편의 제목·본문) + 규칙 "본인이 새로 말한 내용만".
- **[안 만들기] 규칙(지금)**: 안 만든 내용은 다시 제안하지 않는다 — 구간 시작을 카드 경계(`until`)로 옮긴다(전과 같음). 그 뒤 말한 턴만 다음 구간. 안 만들기 안내문도 구간에서 빠진다. 직전에 만든 이야기의 시기 힌트(12.3)는 그대로 둔다.

### 12.2 고친 제목이 지도에 안 보이던 것

### 12.3 새 시기는 인생 단계일 때만 + 직전 시기 이어받기

- 프롬프트: `new` 는 이야기가 인생 단계 자체일 때만(입학·졸업, 취업·이직·퇴직, 이사·상경, 결혼, 군 입대·제대, 자녀 출생, 가게). 놀이·여행·방학·사건·사람 이야기는 그 일이 있던 때를 품은 기존 시기 — 본인이 시절을 직접 말했으면(그때 예시 "고등학교 다닐 때" — §13.2 에서 바꿈) 연도를 따지지 말고 그 시기, 말하지 않았으면 그 해 이전의 가장 가까운 시기. ### 13.1 장소 이름 합쳐짐 → 카드에서 되묻기

- 규칙: 제안 정리 결과의 새 장소 이름이 같은 사용자의 기존 장소 이름을 품거나 둘 이상을 이어 붙인 모양이면(예: 있는 "외할머니 댁"·"개울" + 새 "외할머니 댁 개울") 자동으로 새로 만들지 않고, 동명이인 되묻기와 같은 방식으로 그 행에서 "이미 있는 장소 ○○와 같은 곳인가요?" [같은 곳이에요](후보마다) · [따로 만들기]를 묻는다. 답할 때까지 [만들기] 안 됨, 아무것도 저장 안 함.
- 판정(`lib/node-proposal` `overlappingPlaces`·`placeRow`): 공백 무시, 이름이 같으면 이미 있는 곳(전과 같음), 아니면 새 이름 안에 들어 있는 기존 장소(2자 이상 — "집" 같은 한 글자는 뺌, 최대 3개). 카드 행 `overlap`(이 칸 없는 옛 카드는 저장 쪽이 다시 계산), 저장 쪽(`createFromCard`)이 사람·장소 되묻기를 한 번에 돌려준다(`placeAsk`). [같은 곳이에요] = 후보 안의 장소만(밖이면 거부), 같은 곳을 가리킨 두 줄은 한 번만 연결. 장소 후보 목록은 여전히 AI 에 안 보낸다(Q70 — 비교는 코드).
- 프롬프트: "장소 하나에 이름 하나 — 두 곳이면 두 개로 나눠 쓰고, 두 곳을 이어 붙여 한 이름으로 만들지 마세요".
- 범위 밖: 같은 카드 안에서 새 이름끼리 이어 붙인 경우(기존 장소가 없을 때)는 프롬프트 규칙만.

### 13.3 옛 이야기 제목 정리 + 제목 없음 판정 한 곳

- **제목 없음 = 빈 문자열**(성민 결정, 2026-11-02). `UserMemory.title` 이 NOT NULL 이라 NULL 은 마이그(`DROP NOT NULL`)가 필요하고, 그러면 연혁·가족 소식·가족 방·타임머신·인물·연구실 등 이야기와 무관한 행까지 타입이 바뀌어 약 11개 파일을 고쳐야 했다(로컬 측정 후 되돌림). 빈 문자열이면 마이그 0 으로 같은 효과 — 보이는 글자 그대로 · 본문을 고쳐도 제목이 굳지 않음 · 사용자가 지은 제목과 안 섞임.
