# 결정 — 디자인 토큰 시스템: 밤 우주 단일 테마 (2026-11-05, 라이트 온리 대체)

> 파일 이름은 링크 호환을 위해 그대로 둔다. **지금 유효한 결정은 이 절**이고, 아래 "이전 결정(2026-06-12 라이트 온리)"은 기록이다.
> 결정 로그: 제안 리뷰 채팅 / 결정 성민. 설계(토큰 값·대비 표·범위·단계): `docs/phase/ui-night.md`.

## Problem

- 2026-06-12 결정으로 앱은 밝은 화면만 썼다. 2026-11-05 My Life 우주 개편(U1)에서 밤 우주를 `/my-life` 예외로 들였고, 그 화면 실측에서 밤 값이 글자 4.5:1·테두리 3:1 을 전부 넘었다(`docs/phase/ui-space.md` §7.1).
- 반대로 밝은 테마의 앱 전체 토큰 `brand`(버튼 테두리·포커스 고리 2.57~2.71:1)와 `line`(칸·입력칸 테두리 1.25:1)은 3:1 에 못 미쳤다.
- My Life 만 밤이면 앱 공통 요소(머리 줄·사이드 패널·비서 버튼·공지 띠)와의 경계(Q142)·두 테마 대비 유지가 화면마다 남는다 — 라이트 온리 결정이 경계한 "모드 부채"를 예외로 키우는 셈이다.

## Action(결정)

1. **밤 우주가 Lifebook 단일 테마다.** 2026-06-12 "밝은 화면만"(아래 이전 결정 1)을 대체한다. 바탕은 남보라 + 성운, **검정 금지**(가장 어두운 값 `#221d52`).
2. **밝은 우주는 기본에서 제외.** "밝게 보기" 설정을 둘지는 보류 — 그전까지 밝은 값은 코드에 두지 않는다(설계 Q148 추천, 값은 설계 §1.1 표와 git 기록).
3. **Q142 무효** — 앱 공통 요소도 밤. My Life 예외(아래)는 이 결정에 흡수된다.
4. **이어 유효한 이전 결정:** 토큰 이름 규칙(이전 결정 2 — 크기 키워드 금지), 버튼 위계 5종(결정 3 — 단 primary 글자색은 새 토큰 `on-action`), 선택 칩 필 금지(결정 4), 연대 틴트 워시 전용(결정 5 — 밤 값은 설계 §1.1).
5. **구현 — 2026-11-05 전원 적용(결정 로그 3차: 허용 목록 단계 생략, 로그인 안 함·V3·V2 모두).** 서버가 늘 `<html data-theme="night">`, 화면 코드의 기본 팔레트 색을 토큰으로(설계 §8). 밝은 값은 코드에 남지만 고르는 경로 없음. 원래 계획(참고): 단계: 토큰 → 공통 요소 → 화면별 → 전원(설계 §5). 화면을 다 바꾸기 전엔 허용 목록 계정만 밤(직접 적은 색 115개 파일이 섞인 색이 되는 것과 실고객 V2 화면 보호 — 설계 Q145). `docs/design-system.md` 는 그때 고친다.

## Result(기대 — 구현 뒤 채움)

- 기대: 글자 4.5:1 · 테두리·포커스·입력칸 3:1 을 앱 전체에서 한 벌의 값으로 지킨다(설계 §1.2 표 — 전부 통과). 새 화면의 "두 테마 대비" 부채가 다시 0 이 된다(단일 테마).
- 비용: 직접 적은 색 115개 파일(그중 V2·옛 화면 46개 · 516곳)의 변환, 그림자 대신 바탕 단계·테두리로 층 구분, 긴 글 화면 처리(설계 Q144 — 아이보리 글자 vs 편지지 카드).

### 일반화된 학습(갱신)

- 이전 결정의 학습 1("타깃이 좁으면 모드는 부채다")은 그대로 맞다 — 그래서 **두 모드가 아니라 한 테마를 바꿨다**. 바뀐 것은 "어느 한 벌이냐"이고, 판단 근거는 취향이 아니라 실측 대비(밝은 값의 앱 전체 토큰 미달 vs 밤 값 전부 통과)와 서비스 은유(밤하늘의 기억)였다.

# 이전 결정(2026-06-12) — 디자인 토큰 시스템 (라이트 온리) — **2026-11-05 대체됨(위)**

2026-06-12. 디자이너방 토큰 가이드 v1.0 적용 시리즈(1~5차).
기존 `dark-mode-token-swap.md` 의 다크모드 결정을 **대체(supersede)** 한다.

## Problem

- 화면 전반의 색이 zinc/amber/white 하드코드로 분산 — 페이지마다 미묘하게
  다른 회색·흰색, 일관 정책 부재.
- 다크모드(CSS 변수 swap)가 모든 신규 화면에 "다크 대응" 부채를 지움 —
  실제로 v3 신규 12+ 파일 다크 미대응(M2)이 후속 목록에 계속 쌓였다.
- 핵심 타깃(시니어)에게 다크모드 수요 사실상 0. 회상 서비스의 감성은
  "따뜻한 종이 톤" 단일 무드가 더 적합.
- 버튼·칩·빈 상태가 페이지마다 제각각 구현 — 위계(주요/보조/파괴적)와
  터치 크기(48px+)가 코드 리뷰로만 지켜지는 상태.

## Action

### 결정 1 — 다크모드 폐기, 라이트 단일 팔레트

`ThemeToggle.tsx`·`theme-actions.ts`(쿠키) 삭제, `:root { color-scheme:
light }` 고정. OS 다크 설정과 무관하게 항상 라이트. 토큰이 단일 값이라
"50↔950 대칭" 같은 swap 설계 자체가 사라짐 — 신규 화면의 다크 대응
부채 원천 제거.

### 결정 2 — 토큰 네이밍: 크기 키워드 금지 (base → canvas)

가이드 명칭 "base" 를 `--color-base` 로 정의하면 Tailwind v4 가
`text-base`(글자 크기 유틸리티)를 **색상 유틸리티로 덮어써** 글자색=
배경색 사고. 색 토큰명에 base/lg/sm 등 크기 키워드 금지 → `canvas`.

### 결정 3 — 버튼 위계 5종 + 필 색 단일 원칙 (`components/ui/Button`)

- `primary` = bg-action 필 — **화면당 1개** (주요 CTA).
- `secondary`(brand 보더+action 글자) / `tertiary`(line 보더+ink-soft) /
  `plain`(텍스트형) / `destructive`(**tertiary 형태에 danger 글자만 —
  빨강 필 금지**, 실제 탈퇴 확인 단계 같은 최종 관문에서만 danger 필).
- size md=48px / lg=56px — 시니어 터치 최소를 컴포넌트가 보장.

### 결정 4 — 선택 칩은 필 금지

선택 = `bg-banner + border-brand + text-action`, 비선택 = `bg-surface +
border-line + text-ink-soft`. action 필은 버튼(행동) 전용 — 칩(상태)에
필을 쓰면 "눌러야 할 것"과 "선택된 것"이 구분 안 됨. 진행바 fill 은 brand.

### 결정 5 — 연대 틴트는 워시 전용

decade 틴트 9종 + 스트립 9종. **텍스트 배경 금지** — 스트립(4px)·점·
5~10% 워시만, 틴트 위 텍스트는 ink/ink-soft 만. 저채도 틴트 위 본문
텍스트 대비 미달을 규칙으로 차단.

### 의도적 비치환

음악 rose / 정보 sky / SPORTS blue 등 **의미 분리용** 보조 팔레트와
사이드 패널 amber 강조는 잔존 — 의미색까지 토큰으로 흡수할지는 후속.

## Result

- 100여 파일 치환, 5차 grep 검증 `bg-white|text-black|ThemeToggle` 잔존 0.
- 본문 Pretendard + 제목 Noto Serif KR 로 서체 위계 통일.
- tsc·기존 검증 스크립트 회귀 0.

### 트레이드오프

- 다크모드 복원 시 토큰 값 이원화부터 다시 설계해야 함 — 수요 확인 전엔
  지불하지 않기로 한 비용.
- 보조 팔레트(rose/sky 등) 이원 체계 잔존 — 토큰 단일 진실 원천은 아직
  표면색·위계까지만.

### 일반화된 학습

1. **타깃이 좁으면 모드(다크/라이트)는 부채다** — 모든 신규 화면에
   세금을 매기는 기능은 수요 증거가 생긴 후에.
2. **유틸리티 생성형 CSS 에서 토큰명은 네임스페이스 충돌 검토 필수** —
   색 토큰이 크기 유틸리티를 덮어쓸 수 있다.
3. **위계·터치 크기는 컴포넌트가 보장** — 가이드 문서가 아니라 Button
   variant/size 가 규칙의 집행자.

## 예외 — My Life 밤 우주(2026-11-05, 결정 성민 · 제안 리뷰 채팅) — **같은 날 맨 위 "밤 우주 단일 테마" 결정에 흡수됨**

- `/my-life` 는 밤 우주(남보라 + 성운, 검정 금지) 테마를 지도 안 토글로 고를 수 있다. 범위는 `/my-life` 화면(머리 줄·패널·도구줄 포함). **다른 화면은 이 문서 결정대로 밝게만.** 기기 다크 모드 연동은 보류.
- 방식: `/my-life` 뿌리 요소 안에서만 토큰 CSS 변수를 밤 값으로 다시 정의(컴포넌트 무수정). 전역 `color-scheme: light` 고정은 그대로.
- 위 "일반화된 학습 1"(모드는 부채)을 그대로 받아들인 예외다 — 부채를 `/my-life` 안으로 가둔다. 그 안에 새로 들어오는 화면 요소는 두 테마 대비를 함께 맞춘다.
- 설계·세부 범위(앱 공통 요소·하위 글 화면 포함 여부 Q142): `docs/phase/ui-space.md` §1.7.
