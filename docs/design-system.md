> 2026-07-02 확정. **이상론이 아니라 지금 코드에 이미 있는 패턴을 실측해서
> 정리한 것** — 새 규칙을 발명하지 않았다. 이 문서 자체는 코드 변경 0(문서만).

> 것 vs 이탈"을 가른다.

> 참조. 이 문서는 그 위에서 "무엇을 써야 하는가"를 다룬다.

## 채택 원칙

원티드·토스류 일반 IT 서비스의 **미니멀 원칙**(장식 제거·여백·명확한 위계)은
따르되, **토큰(색·글자 크기·터치 영역)은 우리 것**이다. 타겟이 60~80대
어르신이고 브랜드가 "기록과 존엄"이기 때문에, 그 미니멀 원칙을 그대로
가져온 서비스에 흔한 **차가운 블루·회색 계열 본문·작은 글씨**는 우리
기준에서 탈락이다. 아래 팔레트·타이포는 실제로 지금 코드가 하고 있는 것의
정리이며, 동시에 이 탈락 기준의 근거다.

---

## 1. 3대 원칙

### ① 장식 제거

그라데이션·불필요한 아이콘·과한 섀도우 금지. 실측: 그라데이션은 전체
코드베이스에 **단 2곳**(포스터 템플릿 피커의 슬롯 채움 — 그마저 토큰
`from-banner to-brand/20`)뿐이고, 섀도우는 24곳(16개 파일)뿐 — 대부분
`shadow-sm` 한 단계로, 작은 원형 아이콘 버튼·입력창 hover 에만. **이미
장식이 거의 없는 상태를 유지하는 것**이 원칙이지, 새로 절제를 발명하는
게 아니다.

### ② 목적 중심

각 화면의 핵심 행동이 3초 안에 보여야 한다. `Button` 컴포넌트의
"primary(필 색)는 화면당 1개" 원칙(§4)이 이를 강제하는 장치다 — 주요 CTA가
하나로 명확해야 어르신이 "뭘 눌러야 하는지" 헤매지 않는다.

### ③ 색 제한

팔레트 외 사용 금지. 실측: 브랜드 토큰이 아닌 Tailwind 기본 회색 계열
(`gray-`/`zinc-`/`slate-`/`neutral-`/`stone-`)은 전체에서 **7곳뿐**이고,
전부 텍스트나 배경이 아니라 체크박스 `accent-zinc-900`(3곳)·목록 구분선
`divide-zinc-200`(4곳)이다. 즉 이미 거의 완전히 정착된 원칙 — §5 금지
목록은 이 마지막 7곳까지 마저 정리하라는 신호다.

## 2. 팔레트 (실측 확정)

`app/globals.css` `@theme` 블록이 유일한 소스. 대비는 WCAG 상대휘도
공식으로 배경 `#faf7f0`(canvas) 기준 계산.

| 토큰 | 값 | 용도 | 대비(대 canvas) |
| --- | --- | --- | --- |
| `canvas` | `#faf7f0` | 페이지 배경 | — |
| `surface` | `#fffdf8` | 카드·모달 표면 | — |
| `ink` | `#2a2520` | 본문 텍스트 | **14.2 : 1** (AAA) |
| `ink-soft` | `#5c534a` | 부가 텍스트(캡션·보조 설명) | **7.0 : 1** (AAA) |
| `ink-faint` | `#6e655b` | 희미한 텍스트(진짜 장식용만) | **5.3 : 1** (AA — 셋 중 가장 낮음, 남용 금지) |
| `line` | `#e5decf` | 보더 | — |
| `brand` | `#c8923d` | 브랜드 골드(보더·아이콘 강조) | — |
| `action` | `#8a5f1a` | 주요 버튼 필 배경 | 흰 글자 대비 확보(brand 원색은 흰 글자 대비 1.9:1 이라 버튼엔 금지 — action 으로 분리된 이유) |
| `action-hover` | `#6f4c15` | action 필 hover | — |
| `sage` | `#6b8c5a` | (정의만 있고 현재 미사용 — 예약) | — |
| `danger` | `#b3433b` | 파괴적 액션 텍스트(필 아님) | — |
| `success` / `success-deep` | `#4d7c4d` / `#3e6b3e` | 성공 상태·뱃지 | — |
| `banner` | `#fff8e8` | 안내·강조 박스 배경 | — |
| `decade-*` (9종) + `decade-strip-*` (9종) | — | 연대 틴트. **텍스트 배경 금지**, 스트립(4px)·점·5~10% 워시만 | — |

**핵심**: `ink-soft`(7.0:1)가 "회색 300~400급 저대비 캡션"이 흔히 저지르는
실수를 피한 이유는, 실제로는 회색이 아니라 **어두운 브라운 계열
(`#5c534a`)**이기 때문이다. 저대비를 피하려면 색상을 밝게 하지 말고 원색을
바꿔야 한다 — 이게 이 팔레트가 일반 IT 미니멀(연회색 다용)과 갈라지는
지점.

### 확장 의미색 (허용된 예외 — 이미 정착)

핵심 팔레트 외에 **의미 분리용**으로 Tailwind 기본색을 쓰는 4개 계열이
이미 405곳(83개 파일)에 퍼져 있다: `emerald`(확정·성공 표시, 담음 상태),
`amber`(포커스 링·연대 강조·사이드 패널 강조), `rose`(음악/영상 링크),
`violet`(AI 비서 관련). `sky` 는 정보·안내 톤으로 5곳(사진 첨부 UI).
새로 발명한 게 아니라 [`design-tokens-light-only.md`](decisions/design-tokens-light-only.md)
가 "의도적 비치환"으로 이미 인정한 레이어다. **규칙**: 이 4~5개 계열
밖으로 새 색(예: `teal`, `fuchsia`, `lime`)을 늘리지 않는다 — 의미가
겹치는 색을 추가하면 "의미 분리"라는 존재 이유가 무너진다.

## 3. 타이포그래피 (어르신 기준)

- **본문 기본값이 이미 18px**: `app/layout.tsx` 의 `<body>` 가
  `text-lg`(18px)를 기본으로 깔고, 컴포넌트가 필요할 때만 축소한다.
  일반 서비스처럼 "기본 14~16px + 강조만 확대"가 아니라 **거꾸로** —
  이게 시니어 서비스의 타이포 방향이다.
- **실측 분포**(app/, Tailwind 기본 px 기준):

  | 유틸리티 | px | 개수(파일 수) | 용도 |
  | --- | --- | --- | --- |
  | `text-2xl` | 24px | 86(58) | 화면 제목급 |
  | `text-xl` | 20px | 112(57) | 섹션 제목 |
  | `text-lg` | 18px | 328(106) | **본문 기본**(body 상속과 동일 크기, 명시가 더 많음) |
  | `text-base` | 16px | 436(103) | 본문 하위 위계(폼 라벨 등) — **바닥선** |
  | `text-sm` | 14px | 248(64) | 캡션·보조 설명(예: "그때 O세쯤이에요", "방금 녹음한 내용") — **읽어야 하는 본문에 쓰지 않는다** |
  | `text-xs` | 12px | 58(20) | 뱃지·타임스탬프 등 장식적 라벨만 |
  | `h1`(CSS) | 34px | — | 명조(Noto Serif KR), 페이지 최상위 제목 |
  | `h2`(CSS) | 26px | — | 명조, 섹션 제목 |

- **규칙**: 사람이 **읽고 이해해야 하는 내용**(본문 문단·라벨·안내문)은
  `text-base`(16px) 이상만 쓴다. `text-sm`/`text-xs`는 부가 정보(나이 힌트,
  업로드 개수, 타임스탬프)에 한정 — 실측 확인 결과 지금도 이 규칙을
  대체로 지키고 있다(§0 근거).
- **서체 위계**: 제목 = Noto Serif KR(명조, 문어적·기록물 느낌), 본문 =
  Pretendard(가독성). 브랜드 톤("기록과 존엄")을 제목에만 태우고 본문은
  가독성 우선 — 섞어 쓰지 않는다.
- **캡션도 저대비 금지**: `text-sm`을 쓸 때도 색은 `ink-soft`(7.0:1) 까지만
  — `ink-faint`(5.3:1)와 작은 글씨를 동시에 쓰지 않는다(대비 하락 ×
  크기 축소 이중 페널티 방지).

## 4. 컴포넌트 규칙

### 버튼 (`components/ui/Button.tsx` — 이미 코드로 강제됨)

| variant | 형태 | 용도 |
| --- | --- | --- |
| `primary` | `bg-action` 흰 글자 필 | **화면당 1개** — 주요 CTA |
| `secondary` | `surface` + `brand` 보더 + `action` 글자 | 보조 행동 |
| `tertiary` | 배경 없음 + `line` 보더 + `ink-soft` | 3순위 행동 |
| `plain` | 텍스트형(밑줄) | 카드 안 최하 위계 |
| `destructive` | tertiary 형태에 `danger` 글자만 | **빨강 필 금지** — 진짜 탈퇴 확인 같은 최종 관문에서만 danger 필 예외 허용 |

- **터치 영역**: `md` = 최소 48px, `lg` = 56px. 사용자 지정치(52px)보다
  실제로는 이미 더 넉넉하다 — 48px 은 WCAG 최소치이자 우리 하한선.
- **라운딩**: 버튼은 고정 `rounded-[10px]`(10px) — 카드보다 한 단계
  또렷하게 구분되면서도 캡슐(`rounded-full`)은 아니다.
- **포커스**: `focus-visible:ring-4 ring-brand ring-offset-2` — 키보드
  포커스가 눈에 띄게. 모든 variant 공통.

### 카드 · 컨테이너

- **라운딩 실측**: `rounded-md`(6px)가 552곳(111개 파일)으로 압도적
  표준. `rounded-lg`(24곳)·`rounded-xl/2xl`(31곳)은 드문 예외. 즉 **카드·
  입력창은 `rounded-md` 가 기본값**이고, 버튼만 10px 로 의도적으로 분리된다.
- **경계**: 얇은 보더(`border` + `line` 토큰) OK — 그림자보다 보더로
  경계를 표현하는 게 기본(§1① 과 일치, 섀도우 24곳뿐).
- **클릭 가능한 카드는 명확히 구분**: hover 시 `border-brand`/`bg-banner`
  전환 또는 커서 포인터로 "누를 수 있음"을 시각적으로 분리 — 링크형 카드와
  정보 표시용 카드를 같은 스타일로 섞지 않는다.
- **원형(`rounded-full`)**: 91곳(33개 파일) — 전부 아바타·아이콘 전용
  원형 버튼(예: 44px 화살표 버튼)·작은 점·뱃지 용도이며 **CTA 버튼에는
  쓰지 않는다**(버튼은 항상 10px). 캡슐형 필 버튼 남발 없음 — 이미 지켜짐.

### 아이콘

- 핵심 액션에만 사용(lucide-react). 장식용 아이콘 남발 금지 — 문장마다
  아이콘을 붙이는 패턴은 쓰지 않는다.
- 예외: `EmptyState` 처럼 **화면당 하나의 의미 있는 상태 아이콘**(brand
  색, `strokeWidth 1.75`)은 장식이 아니라 "지금 상태가 무엇인지"를 즉시
  전달하는 기능적 아이콘이라 허용.

## 5. 금지 목록

- **그라데이션 남발** — 브랜드 토큰 조합(예: `from-banner to-brand/20`)
  1~2곳의 미묘한 예외를 넘어서는 그라데이션 확대 금지.
- **저대비 텍스트** — `ink-faint`(5.3:1)보다 낮은 대비의 회색(Tailwind
  `gray-400`/`zinc-400`급)을 본문·캡션에 쓰지 않는다.
- **작은 글씨** — 읽어야 하는 본문·라벨·안내문에 `text-sm` 이하 금지.
  `text-sm`/`text-xs`는 부가 정보 전용(§3).
- **차가운 블루** — `blue-`/`indigo-`/`cyan-` 계열을 UI 크롬(버튼·주요
  액션·본문 강조)에 쓰지 않는다. `sky-`는 이미 정착된 "정보 안내" 의미색
  예외(§2 확장 의미색)로만 제한 사용.
- **과한 라운딩 캡슐 남발** — 버튼에 `rounded-full` 금지(고정 10px).
  카드·컨테이너의 기본은 `rounded-md`(6px) — `rounded-2xl/3xl` 같은 과한
  라운딩을 새로 늘리지 않는다.
- **불투명한 섀도우** — `shadow-lg`/`shadow-xl`/`shadow-2xl` 같은 진하고
  큰 그림자 금지. 쓰더라도 `shadow-sm` 한 단계, 작은 인터랙티브 요소(원형
  아이콘 버튼·입력창 hover)에 한정.
- **팔레트 밖 새 색 추가** — 핵심 9개 토큰 + 확장 의미색 4~5계열
  (emerald/amber/rose/violet/sky) 밖의 색(teal·fuchsia·lime 등)을 새로
  들이지 않는다. 필요하면 먼저 이 문서를 갱신한 뒤에.
- **`gray-`/`zinc-`/`slate-`/`neutral-`/`stone-` 텍스트·배경** — 남은
  7곳(accent 체크박스 3·divide 구분선 4)도 신규 코드에서는 토큰
  (`ink-soft`/`line`)으로 대체. 기존 7곳은 이 문서 범위 밖(문서만, 코드
  변경 0) — 후속 감사·개선 단계에서 정리 대상으로 남긴다.
