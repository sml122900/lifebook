## 1. 버그 — 탈퇴 시 LifeEvent FK 위반

v3 P1~P4에서 `LifeEvent`/`OnboardingProfile`을 추가할 때 다른 모델(Poster·
CompanionSession·OnboardingChatMessage 등)과 다르게 `onDelete: Cascade`를
빠뜨렸다. `tx.user.delete()`가 "Foreign key constraint violated on
LifeEvent_userId_fkey"로 실패 — 회원 탈퇴가 아예 안 되는 상태였다.

- `LifeEvent.user` → Cascade
- `OnboardingProfile.user` → Cascade
- `Episode.lifeEvent` → Cascade (LifeEvent가 User cascade로 지워질 때
  Episode가 고아로 남아 같은 FK 위반을 재발시키는 것을 막음. `Episode.memory`는
  이미 Cascade라 UserMemory 경로는 기존에도 안전했음)

FK DROP + 같은 이름으로 재생성(ON DELETE CASCADE 추가)만 — 컬럼·데이터
변경 없는 순수 제약조건 강화.

## 2. 탈퇴 트랜잭션 공용화 (`lib/account-deletion.ts`)

기존에는 `app/account/delete/actions.ts`의 탈퇴 트랜잭션과 `db/test-
withdrawal.ts`의 검증 로직이 서로 다른 코드로 복붙되어 있었다. 이 상태로는
스크립트가 통과해도 "재현본이 맞다는 증거"일 뿐 실제 액션이 맞다는 보장이
없다 — 검증 방식을 논의하며 나온 지적. `deleteAccountTx(userId)`로 트랜잭션
본체(룸 양도/cascade, 미결제 주문 정리, 룸 댓글 사전 정리, `user.delete`)를
추출해 액션(실사용, auth 게이트)과 스크립트(검증, auth 우회) 양쪽이 정확히
같은 함수를 호출하도록 했다.

## 3. 실검증 — 운영 Supabase 대상, 4 시나리오

`db/test-withdrawal.ts`에 시나리오 4(LifeEvent/Episode/OnboardingProfile/
OnboardingChatMessage cascade)를 추가.

- 테스트 계정 생성 → OnboardingProfile 1 + LifeEvent 3(CONFIRMED 2,
  UNCONFIRMED 1) 생성
- Episode 2건은 **재현이 아니라 실제 프로덕션 함수**
  `lib/episode.ts`의 `createEpisodeBridge()`를 그대로 호출 — UserMemory
  브릿지까지 같은 코드로 생성
- OnboardingChatMessage 2건 생성(`saveChatMessage` 액션은 단순
  `prisma.create` 래퍼라 로직 분기 없어 직접 재현해도 검증 의미 동일)
- `deleteAccountTx()`(액션이 실제로 쓰는 그 함수) 호출 → FK 에러 없이 성공
- 삭제 후 확인: LifeEvent·Episode·OnboardingProfile·OnboardingChatMessage
  고아 **0건**, Episode에 딸렸던 UserMemory(브릿지) 2건도 **0건**
  (User→UserMemory 직접 cascade + Episode→UserMemory 경로 둘 다 안전 확인)
- 기존 시나리오 1~3(룸 양도/cascade, SharedMemory 익명화, 룸 댓글 정리)도
  공용 함수로 갈아탄 뒤 회귀 없이 전부 통과
- 테스트 계정 잔존 0건 확인, `tsc --noEmit` 통과

## 4. v3 채팅 UX 마무리 (같은 커밋)

- **P5-4** — `ChatV3Client` 헤더(캐릭터 포함)를 `sticky top-0`으로 고정.
  캐릭터가 대화 리액션 용도라 스크롤해도 계속 보여야 의미가 있음. 작은
  화면(`sm` 미만)에서는 캐릭터를 제목 아래 줄로 내려 사이드 패널 버튼과의
  겹침을 폭 계산 없이 회피.
- **P5-5** — 확인질문 문구에 `withJosa` 적용해 조사를 자연스럽게
  (`"{label}은 하셨나요?"` → `"{label}은/는 하셨나요?"` 자동 처리) + 시스템
  프롬프트에 "군 입대 하셨나요?"(X) → "군에 입대하셨나요?"(O) 같은 자연화
  규칙 보강.
