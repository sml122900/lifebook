## 0. 요약

- **배치(§1).** 좌표계·순수 배치 함수(`lib/my-life-layout.ts`)·겹침 검사는 그대로 쓴다. 그림 단위만 "노드 상자"에서 **"계(system) 상자"** 로 바꾼다. 계 = 행성 + 궤도 + 위성 + 이름표가 차지하는 고정 사각형이고, 공전은 늘 그 안에서만 일어나므로 **움직여도 겹침이 생기지 않는다.**
  - 시간 줄기는 **세로 한 줄**로 둔다. 시기 행성 → 그 시기 이야기 행성 → 다음 시기 순서다. 390 배율 1에서 계 하나가 화면 폭에 들어가고, 보이는 순서 = 시간 순서 = DOM(낭독) 순서다(Q104).
  - 행성 크기: 이야기 128 고정, 시기 128·144·160(이야기 0~1·2~3·4 이상). 위성이 없는 행성은 궤도 자리를 잡지 않는다(이야기 42/92·시기 105/147 이 해당).
  - 위성 규칙: 첫 궤도 6개, 두 번째 궤도(60° 기울임) 12개까지, 13개부터는 11개 + "+N" 위성(Q108). 위성 이름표는 **행성 원판과 안 겹치는 구간에서만**(궤도 1 은 대략 앞쪽 절반) 보여 행성 글자와 겹치지 않는다(Q107).
  - 인물록·장소록 → 인물·장소 **행성 모음**(진짜 노드 = 작은 행성 64 + 이름), 모임·장소 묶음 Euler 영역 → **성운**(같은 `placeVenn`). 사용자 카테고리(custom-graph 2단계)도 같은 열 아래 성운이고, Q99 바로가기 칸은 **멈춰 있는 위성** 모양으로 통일한다.
- **공전(§2).** 위성마다 CSS `@keyframes`(궤도 모양 2벌 공유, 36걸음) + 음수 `animation-delay` 로 자리를 나눈다. React 는 구조만 그리고 프레임마다 아무것도 하지 않는다. 화면 밖 계(`IntersectionObserver`, 여유 한 화면)·전체 보기 배율(0.6 미만)·탭 숨김·`[움직임 멈추기]`·reduced-motion 에서는 멈춘다.
  - 측정(헤드리스 Chrome, 390×844·DPR 3, CPU 4배 감속, 노드 36·100·300 = 위성 64·160·440, §2.4):
    - 매 프레임 JS(시안 방식의 하한) — 300 에서 메인 스레드 998ms/초(꽉 참)·합성기 프레임 31% 버림.
    - CSS + 화면 밖 정지(채택) — 가만히 메인 1.3~2.0ms/초, 300 에서 지도 끌기 중에도 프레임 p95 8.4ms(120Hz 그대로)·33ms 넘는 프레임 0. **비용이 노드 수와 무관**(도는 계 = 화면 안 3~4개).
    - CSS 전부 공전(화면 밖 정지 없음)은 가만할 때는 괜찮지만 끌기 중 p95 50ms·끊김 83프레임 — 화면 밖 정지와 "전체 보기 배율에서 정지"가 필수인 근거.
    - 배터리 근사(1배, Chrome 전체 CPU): 정지 11 → 채택 방식 105ms/초(한 코어 약 9%) · 매 프레임 JS 663. 와트 추정은 하지 않고 U2 실기기 측정으로 넘긴다.
- **접근성(§3).** 도구줄 `[움직임 멈추기]`(WCAG 2.2.2), reduced-motion 이면 처음부터 정지·나선·출렁임 생략(2.3.3), 끌어 넣기의 버튼 경로(2.5.7), 공전 중 위성은 누르는 곳이 아님(움직이는 표적 금지 — 펼쳤을 때만 56px 버튼). 글자 대비는 두 테마 모두 4.5:1 이상(시안 색 계산), **밝은 우주의 행성·위성 테두리는 배경 대비 1.5~2.3:1 이라 진한 테두리가 필요**하다(1.4.11).
- **끌어 넣기(§4).** react-zoom-pan-pinch 4.2.0 은 움직일 때마다 `panning.disabled` 를 다시 읽는다. 그래서 "8px 안에서 400ms 누름 → 집기 → 그 손가락 동안 지도 이동·확대 끔"으로 충돌 없이 나눌 수 있다. `draggable="true"` 는 쓰지 않는다(라이브러리가 그 요소에서 이동을 시작하지 않음). 놓을 수 있는 쌍은 `saveNodeLink` 허용 쌍 중 1차 6쌍(§4.2).
- **꾸미기(§5).** 서버 저장이면 마이그가 필요하다. 추천은 다형 테이블 `NodeDecoration` 하나(정리 함수 한 줄 추가, 트리거 수 그대로 — 부록 A 초안, 적용 안 함). **AI 꾸미기 제안은 이번 범위에서 제외**(2026-11-05 결정 — 사용자가 고르기만, 처리방침 v1.4 에 넣지 않음). 다시 다룰 때를 위해 감정·성격 판정을 피하는 설계와 처리방침 영향 분석은 §5.2 에 남긴다.
- **글 줄이기(§6).** 390 첫 화면 실측: 지도 120자(버튼 글자 54 · 안내 23 · 지도 안 43), 지도 상자는 화면 844 중 **434px(51%)** 뿐이다(위 285 · 아래 125). 머리 영역 정리로 지도 상자를 약 530px 까지 넓히는 안과 튜토리얼 3단계(행성 누르기 → 끌어 넣기 → AI 에게 묻기)를 제안한다. 3단계는 custom-graph 3a(AI 시트) 뒤에만 붙는다.
- **단계(§7).** U1 정지 우주 → (custom-graph 2단계를 U1 위에 — Q126 결정) → U2 공전 → U3 끌어 넣기 → U4 꾸미기(마이그 — 사용자가 고르기만, AI 제안 U5 는 범위 제외) → U6 튜토리얼. 결정 질문 Q102~Q128 · Q142·Q143(§8).

### 1.2 좌표·크기 규칙(배율 1 = CSS px, 390 실측으로 U1 에서 확정)

- **열.** 시간 줄기 열 = 계 상자 폭 360 + 좌우 여백 → x 40~440, 줄기 x 240. 오른쪽 모음 열 = x 500~(3열 384). 지금의 간선 통로(100px)는 없앤다.
  - 처음 화면은 지금처럼 줄기를 화면 가운데에 둔다 → 390 화면에 x 45~435 가 보여 계 하나가 통째로 들어온다.
- **행성.**
  - 이야기 행성: 지름 128 고정. 안에 제목 20px 굵게 2줄(약 10자) 말줄임. 제목 전체는 펼침·패널·낭독 이름에.
  - 시기 행성: 지름 = 128(이야기 0~1) · 144(2~3) · 160(4 이상). 안에 연도 18px + 이름 20px 2줄.
  - 크기를 이야기 수로만 정하는 이유: 운영 시기당 이야기 최대 4 — 단계가 3개면 충분하고, 위성 수로 키우면 계 폭이 390 을 넘는다.
  - 이야기 행성 크기를 본문 길이·위성 수로 바꾸지 않는 이유: 제목이 들어갈 최소 크기가 128 이고, 키우면 계 폭이 390 을 넘는다(Q105).
- **궤도**(행성 반지름 R, 위성 반지름 r = 24).
  - RY = R + 32, RX = max(128, RY + 16). → 이야기(R 64) RX 128·RY 96 / 시기 160(R 80) RX 128·RY 112.
  - **RY ≥ R + r + 8** 이라 위성이 행성 원판을 지나가지 않는다 — 앞뒤 가림(z-index 바꾸기, 합성기에서 못 함)이 필요 없다.
  - 두 번째 궤도 = 같은 타원을 60° 기울임(시안 "원자 오비탈"). 짧은 반지름이 RY 그대로라 역시 행성과 안 겹친다.
- **위성.** 보이는 원 48(머리글자 18px 굵게) + 누르는 영역 56(펼쳤을 때만 — §3). 이름표 폭 104(18px 1줄 말줄임, 약 5자), 위성 아래 4px.
- **계 상자**(겹침 검사 단위 — 궤도·위성·이름표가 다 들어감).
  - 위성 없음: (지름 + 32) 정사각형 → 이야기 160×160.
  - 궤도 1개: 폭 2 × (RX + 52) = 360 · 높이 2 × (RY + r) + 30 → 이야기 270, 시기 160 이면 302.
  - 궤도 2개: 기울인 타원의 세로 반폭 √(RX²·sin²60° + RY²·cos²60°) = 121(이야기) → 높이 2 × (121 + 24) + 30 = 320.
  - 펼침 자리(§2.3)도 이 상자 안에 둔다.
- **세로 쌓기.** 계 사이 16, 띠(시기 하나와 그 이야기들) 사이 40. 줄기는 행성 뒤로 지나간다.
- **크기 비교(계산 — 실측 아님).** 운영 중앙값 계정(행성 9, 위성 2)은 지금 시간 줄기 약 1,750px → 우주 약 2,700px(1.5배). 위성 없는 행성이 작은 상자(160)를 쓰는 덕에 2배까지 늘지 않는다. 전체 보기 배율(폭 약 900 기준)은 390 에서 0.43 — 지금처럼 0.6 미만이라 "전체 보기 상태"(탭 = 확대, Q60) 규칙이 그대로 맞는다.

### 1.3 위성 규칙 — 궤도 수 상한과 "+N"(Q108)

| 위성 수 n | 궤도 | 보이는 위성 |
|---|---|---|
| 0 | 없음(계 상자 작게) | — |
| 1~6 | 궤도 1 | n개, 360°/n 간격 |
| 7~12 | 궤도 1(6개) + 궤도 2(60° 기울임, n − 6개) | n개 |
| 13 이상 | 궤도 1·2 | 11개 + **"+N" 위성**(N = n − 11) — 누르면 그 행성 펼침 + 패널의 전체 목록 |

- **상한을 궤도 2개로 두는 이유:**
  1. 390 배율 1에서 궤도 3개(원자 기호 모양)면 위성 18개 + 이름표가 계 하나에 겹쳐 읽을 수 없다.
  2. 끌기·확대 중 비용은 화면 안에서 도는 위성 수에 비례한다(§2.4 B).
  3. 운영 최대 3개 — 상한에 닿을 일이 당분간 없다.
- 어느 위성이 "+N" 으로 들어가는지: 지금 칩 순서의 뒤쪽(장소 → 모임 → 사람 순으로 먼저 숨음). 대상 인물(`Episode.personId`)은 늘 보인다.
- 같은 궤도 위성은 함께 돌아 서로 부딪히지 않는다. 궤도 1·2 의 위성은 두 타원이 만나는 네 점에서 잠깐 겹칠 수 있다 — 읽기는 펼친 상태에서 하므로 받아들인다(§2.3).
- **이름표는 행성 원판과 겹치지 않는 구간에서만 보인다(Q107).** 그 밖에서는 머리글자 원만 보인다.
  - 궤도 1 은 대략 앞쪽(아래) 절반(각도 20°~160°)이다. 기울인 궤도 2 는 앞쪽이라도 행성 왼쪽 위를 지나는 구간이 있어(예: 지역 각도 150° → 위성 (−97, −72), 이름표가 원판에 닿음) 각도가 아니라 **기하로** 정한다 — 키프레임을 만들 때 걸음마다 "이름표 사각형이 원판 + 8px 과 겹치나"를 계산해 불투명도 0/1 을 정한다.
  - 이유: 시안처럼 이름표를 늘 보이면 궤도 위쪽에서 이름표가 행성 제목 위로 지나가거나, 그러지 않으려면 궤도를 키워 계 폭이 390 을 넘는다(이름표 104 기준 계산 412px).
  - 불투명도 키프레임은 위성 위치 키프레임과 같은 주기·같은 지연이다(합성기에서 돎 — §2.1).

### 1.4 겹침

- 계 상자끼리는 지금 `findOverlaps`·`resolveOverlaps`(시간 줄기)를 그대로 쓴다. 공전·펼침은 상자 밖으로 나가지 않으므로 **움직이는 동안 새 겹침이 생기지 않는다.**
- 회귀(`test-my-life`)에 더할 검사: ① 모든 궤도 점 + 위성 반지름 + 이름표가 계 상자 안 ② 궤도 짧은 반지름 ≥ R + r + 8 ③ 펼침 자리 전부 계 상자 안·서로 56px 이상 떨어짐 ④ 픽스처 위성 0·3·6·7·12·13·30개에서 궤도 수·"+N" 값 ⑤ 지금 검사(겹침 0·소속 0·`shifted` 0·종류별 x 범위) 그대로.
- 성운(모임·장소 묶음·카테고리)은 지금 `placeVenn` 소속 검사(각 칸이 자기 영역 안·다른 영역 밖)를 칸 크기만 바꿔 그대로 쓴다.

### 1.5 찾기·항로

- **찾기 빛남.** 결과를 누르면 그 노드의 진짜 자리 + 그 노드를 가리키는 **모든 위성**에 빛 표시를 한다(바로가기 키 목록은 배치 결과에서 바로 나옴).
  - 빛은 색만으로 알리지 않는다(1.4.1) — 두꺼운 고리 + 점선 바깥 고리를 같이 쓴다. reduced-motion 이면 깜빡이지 않는 고정 고리.
  - 공전 중인 위성도 고리가 요소에 붙어 함께 돈다(그림 한 번, 움직임은 합성기).
  - 결과 줄의 `[연결된 곳 차례로 보기(N)]`(지금 기능 재사용)는 진짜 자리 → 그 분·곳이 위성으로 있는 행성들을 **시간 순서**(배치 순서)로 하나씩 간다.
- **항로 보기(Q113).** 사람·장소(진짜 노드 또는 위성)를 골랐을 때만 선택 줄에 `[문구 필요: 항로 보기]` 토글 하나가 보인다.
  - 켜면 그 분·곳이 위성으로 있는 **행성 중심들**을 시간 순서로 잇는 곡선(SVG, 지금 `lib/my-life-edges.ts` 의 곡선 재사용)을 그리고, 그 행성들의 해당 위성에 빛 표시를 한다.
  - 위성 자체를 잇지 않는 이유: 위성은 움직이므로 선 끝도 매 프레임 바뀌어야 한다(매 프레임 계산 = 금지한 방식). 행성은 움직이지 않는다.
  - 지금의 `[인물 간선 끄기][장소 간선 끄기]` 두 버튼은 없앤다(선택 줄 글자 −12자, 버튼 −1). 행성(이야기·시기)을 골랐을 때는 위성이 곧 연결이라 선을 그리지 않는다(Q114 — Q55·Q57 대체).

### 1.6 사용자 카테고리(custom-graph 2단계)와의 관계

- custom-graph §3 의 영역 규칙(제목·추가 줄·묶음 Euler·접힘·이동 줄 `[다른 카테고리]`)은 그대로 두고 **모양만** 우주로 바꾼다: 영역 = 카테고리 성운, 사용자 항목 = 작은 행성, 바로가기 칸 = 멈춰 있는 위성(점선 고리, 탭 = 원래 노드 패널 — Q99 그대로).
- 사용자 항목에 관련 연결된 이야기(`EPISODE>CUSTOM` 관련 "")는 그 이야기 행성의 위성으로 보인다(지금 칩 계획 `ChipKind` `custom` 과 같은 자리).
- 두 작업이 모두 `MyLifeView`·`layoutRegion` 을 크게 바꾸므로 순서를 정해야 한다(Q126 — §7).

### 1.7 테마(Q102 결정 · Q103)

**Q102 결정(2026-11-05):** 밤 우주는 **`/my-life` 화면 전체**(머리 줄·패널·도구줄 포함)에 쓴다. 다른 화면은 밝게 둔다. 전환은 **지도 안 토글**이고, 기기 다크 모드 연동은 보류한다.

- **라이트 온리 결정(2026-06-12)의 My Life 예외다.** 그 결정이 다크모드를 버린 이유는 "모든 새 화면에 다크 대응 부채가 쌓인다"였다(`docs/decisions/design-tokens-light-only.md`). 예외를 `/my-life` 하나로 묶어 부채를 그 화면 안에 가둔다. 다만 앞으로 `/my-life` 안에 들어오는 것(custom-graph 2단계 카테고리 영역·3a AI 시트·꾸미기 고르기)은 **두 테마를 같이 만들어야** 한다 — 각 단계 완료 기준에 "밤 우주 대비"를 넣는다.
- **구현 방식(코드 변경은 U1):** `/my-life` 뿌리 요소에 테마 표시(`data-space="night"` 꼴)를 달고, 그 안에서만 토큰 CSS 변수(`--color-canvas`·`--color-surface`·`--color-ink`·`--color-ink-soft`·`--color-line`·`--color-action`·`--color-banner`·`--color-brand` 등)를 밤 값으로 다시 정의한다. 버튼·패널·시트는 이미 토큰을 쓰므로 **컴포넌트 코드는 그대로** 따라온다. 그 범위 안에서만 `color-scheme: dark`(입력칸·스크롤바).
  - 패널·찾기 시트·만들기 시트(`<dialog>`)는 `MyLifeView` 안에 그려진다(`app/my-life/MyLifeView.tsx:437·490·502·525`) — 화면 맨 위 층에 떠도 CSS 변수는 DOM 조상에서 물려받으므로 밤 값이 적용된다. `body` 로 옮겨 그리는(포털) 것이 있으면 빠지므로 U1 에서 grep 으로 확인한다(지금 `app/my-life` 에 포털 0).
- **토큰:** 우주 전용 `--color-space-*`(배경 그라데이션 끝값·별·궤도·빛) + 밤 범위에서 다시 정의하는 기본 토큰 한 벌. 크기 낱말 금지 규칙을 지킨다.
- **시안 값**(계산 대비는 §3.3): 밝음 배경 #ECE6FF → #F7F0FF → #FFF0E6, 글자 #2A2350·보조 #4F4878 / 밤 배경 #221D52 + 성운(보라 #BE78FF 35%·파랑 #5AA0FF 30% 방사형), 글자 #F1EEFF·보조 #D3CCF5. 밤도 검정 없음(가장 어두운 값 #221D52). 패널·버튼·입력칸의 밤 값은 시안에 없어 U1 에서 정하고 대비를 잰다(§3.3 끝).

## 2. 공전 구현

### 2.1 방식 — 매 프레임 JS 없음

- **키프레임 공유.** 궤도 모양마다 `@keyframes` 한 벌(타원 위 36걸음 `transform: translate(x, y)`)을 만든다. 모양은 2벌(궤도 1, 60° 기울인 궤도 2) × 행성 크기 단계 수뿐이다. 순수 함수(`lib/space-orbit.ts` 가칭)가 CSS 글을 만들어 화면에 한 번 넣는다.
- **자리 나누기.** 위성 k(궤도 안 n개 중 k번째)는 `animation-delay: −(k/n) × 주기`. 시작 시각이 달라도 모든 위성이 문서 시계 하나에 맞춰 돈다.
- **이름표 보임.** 이름표에 같은 주기·같은 지연의 불투명도 키프레임(원판과 안 겹치는 걸음 1, 겹치는 걸음 0, 경계 한 걸음 페이드 — §1.3)을 단다. transform·opacity 만 움직이므로 둘 다 합성기에서 돈다.
- **React 가 하는 일.** 계·행성·위성 DOM 을 한 번 그리고, 상태가 바뀔 때(멈춤·펼침·화면 밖) 클래스만 바꾼다. 프레임마다 setState·스타일 쓰기 0.
- **멈춤**은 `animation-play-state: paused`(지도 뿌리 클래스 하나) — 그 자리에서 멈추고 재개 때 튀지 않는다.
- **화면 밖 정지.** 계마다 `IntersectionObserver`(root = 지도 상자, `rootMargin` 100% = 위아래로 한 화면 여유). 밖으로 나간 계는 `animation: none` 으로 바꿔 **합성기 레이어 자체를 없앤다**(일시정지는 레이어가 남음). 다시 들어오면 문서 시계로 지연을 다시 계산해 붙인다 — 여유 한 화면 안에서 붙으므로 사용자는 튀는 것을 보지 않는다.
- **전체 보기 배율(0.6 미만)에서는 전부 멈춤.** 이때 위성은 지름 20px 안팎이라 움직임이 의미가 없고, 모든 계가 화면 안이라 화면 밖 정지가 아무것도 줄이지 못한다(§2.4 측정: 이 경우가 가장 비쌈).
- **탭 숨김**은 브라우저가 알아서 그리기를 멈춘다(추가 코드 0).

### 2.2 멈추는 조건 정리

| 조건 | 동작 |
|---|---|
| 도구줄 `[움직임 멈추기]` 켬 | 지도 전체 정지(기기별 기억 — §3) |
| `prefers-reduced-motion: reduce` | 처음부터 정지 + 버튼은 `[문구 필요: 움직이기]` 상태 · 나선·출렁임·튕김 = 바로 그 자리로 |
| 배율 < 0.6(전체 보기 상태) | 전부 정지(배율이 다시 0.6 이상이면 재개) |
| 계가 지도 상자 + 한 화면 여유 밖 | 그 계만 애니메이션 제거 |
| 행성을 눌러 펼침 | 그 행성 위성만 정지·펼침(다른 계는 계속 돎) |
| 끌어 넣기 중 | 계속 돎(놓을 행성을 찾는 데 방해 안 됨 — 놓을 행성은 "자석" 표시, §4.3) |
| 탭이 안 보임 | 브라우저가 멈춤 |

### 2.3 행성 누르기 = 펼침(Q110)

- **탭 한 번** = 그 행성 위성 정지 + 펼침 + 지금처럼 패널(한 번 탭 = 패널 규칙 유지). 패널이 화면 아래를 가리므로 지금의 `zoomAbovePanel` 처럼 펼친 계를 패널 위로 옮긴다.
- **펼침 자리:** 계 상자 안 아래쪽 반원(앞쪽)에 같은 간격으로, 12개면 두 줄 부채꼴. 위성은 56px 버튼이 되고 이름표는 전부 보이며 2줄까지(약 10자).
- **움직임:** 지금 계산된 위치(`getComputedStyle` 의 transform)를 인라인으로 고정 → 애니메이션 제거 → 300ms transition 으로 펼침 자리. 재개는 반대로 펼침 자리 → 문서 시계 기준 궤도 자리로 300ms(Web Animations, 합성기) 뒤 무한 공전. reduced-motion 이면 둘 다 즉시.
- **재개:** 같은 행성을 다시 탭 / 다른 행성·빈 곳 탭 / Esc / 패널 닫기. 다른 행성을 탭하면 앞 행성 재개 + 새 행성 펼침.
- **위성 탭(펼쳤을 때만):** 그 사람·장소의 패널(Q99 바로가기 규칙 — 지도는 안 움직임) + 패널에 `[문구 필요: 원래 자리로 가기]`.

### 2.4 측정 — CPU 4배 감속, 노드 36·100·300

- **조건:** 헤드리스 Chrome 156, 390×844·DPR 3·모바일 흉내, CPU 4배 감속(`Emulation.setCPUThrottlingRate`). 헤드리스 화면 주사율은 120Hz(프레임 8.3ms)라 16.7ms = 한 프레임씩 건너뜀.
- **시제품:** 계 상자 배치를 흉내 낸 정적 HTML(앱 코드 아님). 노드 36·100·300 = (시기·이야기·사람·장소) 8·16·8·4 / 20·40·25·15 / 40·120·90·50. 위성은 **운영 최댓값을 모든 행성에** — 이야기마다 3·시기마다 2 → 64·160·440개.
- **방식 4가지:**
  - 정지(공전 없음)
  - 매 프레임 JS — rAF 에서 위성 transform 을 모두 씀. 시안의 매 프레임 setState 의 **하한**이다(React 재조정 비용은 빠짐)
  - CSS 전부 — 모든 계 공전
  - CSS + 화면 밖 정지 — `IntersectionObserver`(여유 50%)
- **지표:** 메인 스레드 사용(ms/초 — `TaskDuration`) · 합성기 프레임(추적 `PipelineReporter` — 버린 프레임 비율·화면에 나간 프레임 간격 p95) · 끌기 중 rAF 간격 p95(라이브러리처럼 매 프레임 지도 transform 을 바꾸는 흉내, 6초) · Chrome 전체 프로세스 CPU 시간(1배에서 — 배터리 근사).

**A. 가만히 볼 때(4배 감속)** — 메인 스레드 ms/초 · 버린 프레임

| 노드(위성) | 정지 | 매 프레임 JS | CSS 전부 | **CSS + 화면 밖 정지** |
|---|---|---|---|---|
| 36(64) | 1.1 | 407 · 0% | 6.3 · 0% | **2.0 · 0%**(도는 계 3) |
| 100(160) | 0.3 | 655 · 0.1% | 1.9 · 0% | **1.3 · 0%**(3) |
| 300(440) | 0.6 | **998 · 30.7%**(간격 p95 25.0ms) | 1.5 · 0%(8.4ms) | **1.5 · 0%**(3) |

**B. 끌기(지도 이동) 중(4배 감속)** — 메인 스레드 ms/초 · rAF 간격 p95 · 33ms 넘는 프레임 수(6초)

| 노드 | 정지 | 매 프레임 JS | CSS 전부 | **CSS + 화면 밖 정지** |
|---|---|---|---|---|
| 100 | 226 · 8.4 · 0 | 771 · 8.4 · 0 | 952 · 16.7 · 0 | **304 · 8.4 · 0** |
| 300 | 352 · 8.4 · 0 | 1,004 · 25.0 · 0(합성기 버림 34%) | **987 · 50.0 · 83** | **463 · 8.4 · 0** |
| 300 · 전체 보기 배율 0.34 | 454 · 8.4 · 0 | — | **994 · 41.7 · 79** | (모든 계가 화면 안 → CSS 전부와 같음) |

**C. 1배(감속 없음) 가만히, 노드 300** — Chrome 전체 프로세스 CPU ms/초: 정지 11 · **CSS + 화면 밖 정지 105** · CSS 전부 269 · CSS 전부 + 전체 보기 316 · 매 프레임 JS 663.

**읽은 것:**
1. **매 프레임 JS 는 노드 수에 비례해 메인 스레드를 먹는다.** 300 에서 4배 감속이면 메인 스레드가 꽉 차고(998ms/초) 합성기 프레임 31% 를 버린다. 시안 방식을 쓰지 않는 근거.
2. **CSS 공전은 가만히 볼 때 메인 스레드를 거의 안 쓴다**(1.5~6.3ms/초 — 합성기가 돌림).
3. **그러나 끌기·확대 중에는 메인 프레임마다 도는 애니메이션 전부의 스타일을 갱신한다.** 전부 공전시키면 300 에서 지도 끌기가 끊긴다(p95 50ms, 33ms 넘는 프레임 83개). 공전 자체는 합성기에서 계속 매끄럽고, 끊기는 것은 사용자가 끄는 지도다.
4. **화면 밖 정지를 하면 도는 계가 화면 안 3~4개로 고정돼 비용이 노드 수와 무관해진다.** 300 에서도 끌기 p95 8.4ms(120Hz 그대로), 정지 대비 메인 +111ms/초(352 → 463).
   - 시제품의 여유는 50% 였다. 설계안(§2.1)의 여유 한 화면(100%)이면 도는 계가 5~6개로 늘고 이 추가분도 비례해 는다 — U2 완료 기준 2 로 실제 앱에서 다시 잰다. 여유를 두는 이유는 빠르게 튕겨 넘길 때 멈춰 있던 위성이 화면 안에서 제자리로 튀는 것을 막기 위해서다.
5. **전체 보기 배율에서는 모든 계가 화면 안이라 화면 밖 정지가 소용없다**(끌기 p95 41.7ms) → 배율 0.6 미만 전부 정지 규칙(§2.1)의 근거.

### 2.5 배터리 영향 추정

- 근사값은 1배에서 Chrome 전체 프로세스 CPU 시간이다(데스크톱). 헤드리스는 합성을 GPU 대신 CPU 로 하므로 폰의 GPU 일까지 CPU 시간으로 잡힌다 — 상대 비교용이다.
- 노드 300, 가만히: 정지 11 → **채택 방식(CSS + 화면 밖 정지) 105ms/초 = 정지 대비 +94, 한 코어의 약 9%** → CSS 전부 269 → 매 프레임 JS 663.
  - 채택 방식은 매 프레임 JS 의 약 1/6, 전부 공전의 약 2/5 이고, **노드 수와 무관**하다(화면 안 계 수에만 비례).
- 폰에서는 합성이 GPU 로 가고, 120Hz 화면이면 프레임이 두 배라 비용도 는다. **와트 단위 추정은 하지 않았다**(근거 없는 숫자가 됨). 대신 U2 완료 기준에 실기기 측정을 넣는다: Android = Chrome 원격 디버깅 Performance monitor CPU 사용률 + 화면 켜짐 10분 배터리 %(정지·공전 번갈아 2회씩), iOS = Safari 웹 인스펙터 타임라인 에너지 영향.
- **Q111 추천:** "손대지 않으면 자동 정지"는 **처음에는 넣지 않는다.** 가만히 볼 때 비용이 작고 "평소 계속 돎" 확정 사항을 지키는 쪽이다. U2 실기기에서 화면 켜짐 10분 배터리 소모가 정지 대비 1.5배를 넘으면 그때 "N분 손대지 않으면 정지(손대면 재개)"를 더한다(기준값 1.5배도 결정 대상).

### 2.6 U2 완료 기준(공전)

1. 공전에 `requestAnimationFrame`·프레임마다 setState·스타일 쓰기 0(정적 검사 회귀 — 공전 모듈에 rAF 호출 없음).
2. 실제 앱(react-zoom-pan-pinch 안), 픽스처 노드 300(위성 440)·390·DPR 3·CPU 4배 감속:
   - 가만히: 메인 스레드 ≤ 10ms/초 · 합성기 버린 프레임 0%
   - 끌기 3초·두 손가락 확대 3초: 프레임 p95 ≤ 16.7ms · 50ms 넘는 긴 작업 0(custom-graph §3.3 과 같은 기준)
3. 도는 계 수 = 화면 안 + 여유 한 화면 안만(노드 36·100·300 에서 같은 수) · 배율 0.6 미만 = 0.
4. 1배 가만히 Chrome 전체 프로세스 CPU 가 정지 대비 +150ms/초 이하(이번 시제품 +94).
5. 실기기(iOS·Android 각 1대) 화면 켜짐 10분 배터리: 정지·공전 비교 기록 → Q111 결정.
6. 멈춤 → 재개, 화면 밖 → 안: 위성이 튀지 않음(같은 자리에서 이어짐 — 스크린샷 2장 비교).
7. reduced-motion 흉내(`Emulation.setEmulatedMedia`)에서 도는 계 0 · 버튼 `[움직이기]` 상태 · 펼침·넣기 연출 즉시.

### 3.2 키보드·화면 낭독 순서 — 움직임과 무관하게 시기 순

- DOM 순서 = 시기 순(`sequenceOrder`): 시기 행성 → 그 시기 이야기 행성들 → 다음 시기 … → 인물 행성 모음 → 장소 행성 모음 → 카테고리 성운. 지금 규칙(지도 DOM = 시기 순 목록 → 인물록 → 장소록)과 같다.
- **공전 중:** 위성 목록은 `aria-hidden`·포커스 안 감. 행성 버튼 낭독 이름에 위성을 넣는다 — `[문구 필요: 행성 낭독 이름 — 예 "운동회 날 줄다리기, 1962, 함께 나온 분 2명·장소 1곳"]`.
- **펼침(Enter·Space = 탭과 같음):** 위성이 행성 바로 뒤 DOM 자리의 목록(`<ul>`)으로 들어와 Tab 으로 차례로 간다(사람 → 모임 → 장소). Esc = 접고 행성으로 포커스.
- 화면에 보이는 위성의 위치(공전 각도)는 순서에 영향을 주지 않는다.
- 상태 알림(`aria-live`): 펼침·재개·멈춤·넣기 결과는 지금 `announce` 줄 하나로. 공전 자체는 알리지 않는다.
- 목록 보기(`?view=list`)는 움직임 없는 대체 경로로 그대로 둔다.

## 4. 끌어 넣기

### 4.1 손짓 판정 — 지도 이동·두 손가락 확대와 나누기

라이브러리 확인(react-zoom-pan-pinch 4.2.0 `dist/index.esm.js`):
- 이동 시작은 `touchstart`·`mousedown`(포인터 이벤트 아님). 시작 판정 `isPanningStartAllowed` 가 `panning.excluded` 클래스와 **`[draggable="true"]` 요소**를 거부한다.
- 이동 중에는 움직일 때마다 `isPanningAllowed` 가 `setup.panning.disabled` 를 다시 읽는다. props 가 바뀌면 `update()` 가 setup 을 다시 만든다 → **손가락을 뗀 적 없이도 이동을 끌 수 있다.**
- 두 번째 손가락이 닿으면 `onPinch`(별도 `pinch.disabled`).

### 4.3 놓기·피드백·되돌리기

- **판정:** 놓은 점이 행성 궤도 타원(정규화 거리 1.7 안 — 시안 값, 화면 배율 반영)이면 넣기, 아니면 튕겨 돌아옴(520ms, 시안의 outBack). 계를 세로로 쌓으므로(간격 16) 이웃 행성의 1.7 범위가 겹칠 수 있다 → 겹치면 정규화 거리가 더 작은 행성. 끄는 동안 "자석" 표시도 그 한 행성에만.
- **넣기 연출(시안):** 놓은 자리에서 나선 760ms(2.4 라디안 감기며 궤도로) → 진동 18ms → 행성 출렁임 900ms(감쇠 사인) → 새 위성이 궤도에서 자기 자리(문서 시계 기준)로. 서버 응답을 기다리지 않고 연출을 시작하되, **실패하면 위성이 궤도에서 빠져 원래 자리로 돌아가고** 오류 문구(지금 `E.*`).
- **되돌리기:** 넣은 뒤 상태 줄에 `[되돌리기]`(지금 `undoLinks` — 새로 생긴 것만, 다음 동작 전까지).
- 연출도 transform·opacity 키프레임(Web Animations)으로 — 매 프레임 setState 없음.

### 4.4 버튼 경로(유지)

- 패널의 `[인물 넣기]`·`[장소 넣기]`·`[이야기 추가]`(지금) 그대로. 넣고 나면 같은 넣기 연출(나선)을 보여 준다 — 시안 "버튼으로 넣기"와 같다.

## 5. 행성 꾸미기

### 5.1 저장 — 마이그 필요

- 기기에만(`localStorage`) 두면 마이그는 0 이지만, 다른 기기·가족 기기에서 사라진다. 어르신은 자녀 기기로 보는 일이 많아 **서버 저장을 추천**한다 → **마이그 필요.**

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A(추천)** 다형 테이블 `NodeDecoration` | `(nodeType, nodeId)` 유일 + `shape` 문자열 | 꾸밀 수 있는 노드가 늘어도(인물·장소 행성, 사용자 항목) 마이그 0 · `NodeBody` 와 같은 결 | 노드를 지울 때 정리가 필요 → 기존 함수 `node_graph_cleanup()` 에 DELETE 한 줄(트리거 수 8 그대로) + 정합 점검 15(노드 없는 꾸미기) |
| B `LifeEvent.decoration`·`Episode.decoration` 칸 | 행에 붙음 | 정리 트리거·점검 불필요 | 꾸밀 수 있는 것이 이야기·시기뿐. 인물·장소 행성까지 넓히면 칸이 계속 늚. 핵심 테이블 변경 |

- A 초안은 부록 A(적용 안 함, 승인 필요). 값 목록은 코드(`lib/space-decor.ts` 가칭)만 — DB CHECK 없음(custom-graph Q75 와 같은 결).
- 1차 범위(Q119·Q120): 행성 하나에 꾸미기 하나, 대상 = 이야기·시기 행성. 인물·장소 행성은 A 라면 마이그 없이 나중에 열 수 있다.
- 꾸미기 이름 = **모양**(고리·태양풍·혜성 꼬리·블랙홀·오로라 …). "행복"·"슬픔"·"성공" 같은 뜻 이름을 쓰지 않는다. 화면 이름은 `[문구 필요: 꾸미기 이름 N개]`.
- 꾸미기는 계 상자 안에서만 그린다(혜성 꼬리·태양풍 길이 상한 = 상자 경계). 움직이는 꾸미기(오로라 일렁임 등)는 공전과 같은 멈춤 규칙(§2.2)을 따른다.
- 고르는 곳: 행성 패널 `[문구 필요: 꾸미기]` → 모양 그림 격자(누르는 칸 56 이상, 낭독 이름 = 모양 이름) → 고르면 바로 반영 + `[되돌리기]`. `[문구 필요: 꾸미기 없애기]`.

### 5.2 AI 제안과 처리방침 — **이번 범위에서 제외(2026-11-05 결정, Q121)**

- 결정: 꾸미기는 **사용자가 고르기만** 한다. AI 제안은 만들지 않고, 처리방침 v1.4 에도 넣지 않는다. 필요해지면 v1.5 개정과 함께 다시 설계한다.
- 아래 분석은 그때를 위해 남긴다(감정·성격 판정을 피하는 설계·처리방침 영향).


- 확정 원칙: **AI 는 제안만**, 자동 지정 금지. 제안은 사용자가 물을 때만 낸다 — 위치는 custom-graph §4 의 AI 지도 시트(3a·3b)다. 자유 대화(`/chat-v3`)는 꾸미기를 제안하지 않는다(회상 대화와 경계 — custom-graph §4.1 과 같은 결).
- **감정·성격 분류에 해당하는가.**
  - 개인정보 보호법의 민감정보(제23조 — 사상·신념, 정치적 견해, 건강 등)에 "감정"은 없다. 그러나 AI 가 이야기 본문을 읽고 "기쁜 이야기라 오로라" 식으로 고르면, 결과물은 모양이어도 **과정은 감정 판정**이다. `node-graph-self.md` §5.1 이 자아 추천을 "일반적 의미의 프로파일링으로 보고 고지·동의를 설계하는 것이 안전"이라고 본 것과 같은 이유로, 감정·성격을 근거로 고르게 두면 같은 수준의 고지가 필요하다.
  - 처리방침 1항 "회원님이 회상에 자발적으로 민감정보를 적으시더라도, 이를 프로파일링이나 … 사용하지 않습니다"(`app/privacy/page.tsx:213-215`)와도 부딪칠 수 있다 — 건강 이야기를 근거로 꾸미기를 고르면 그 문장 위반으로 읽힌다.
- **추천 설계(감정·성격 판정이 되지 않게):**
  1. 근거는 **구체적인 소재**만 — 장소의 종류(바다·산·학교), 하는 일(여행·운동회·이사), 위성 수·이야기 수 같은 셀 수 있는 것. 지시문에 "감정·성격·건강·관계의 좋고 나쁨으로 고르지 말 것"을 고정한다.
  2. 출력 = 모양 후보 2~3개 + 근거 한 줄. 근거 문장을 **코드로 거른다** — 감정 낱말(기쁜·슬픈·외로운 …)·성격 낱말·`node-graph-self.md` §2.2 금지 꼬리표 목록(진단명·성격유형·건강·종교·정치·성적 지향)이 있으면 그 후보를 버린다(2중 방어 — 프롬프트 + 코드, R3 규칙 7 과 같은 결).
  3. 근거·후보는 **저장하지 않는다.** 저장되는 것은 사용자가 고른 모양 하나뿐이고 `source` 칸에 "AI 후보 중 고름"만 남긴다(부록 A).
  4. 민감정보가 든 이야기를 걸러 낼 표시가 지금 없으므로, 1차 입력은 **본문 대신 제목·위성 이름·장소 이름·셀 수 있는 값**으로 한정하는 안을 추천한다(Q121). 본문까지 보내야 근거가 좋아지면 3d(이야기 본문 근거 질문)와 같은 시점에 다시 본다.
- **처리방침 영향:** 보내는 항목(이야기 제목·사람·장소 이름)은 3항 목록 안이다. 목적에 "기록 지도 꾸미기 제안"은 없다 → **2항·3항 목적에 그 말을 더하는 개정이 AI 제안 배포의 선행 조건**이다.
  - v1.4(custom-graph — 아직 공지 전, `POLICY_NOTICES` 빈 배열)에 함께 넣으면 공지가 한 번으로 끝난다. 다만 v1.4 공지를 이 결정 때문에 늦추지는 않는다 — 늦어지면 v1.5(Q121).
  - 업체·국가가 그대로라 동의 버전 4 유지(v1.2·v1.3·v1.4 결정과 같음).
  - 사용자가 직접 고르는 꾸미기(U4)는 AI 를 거치지 않으므로 처리방침 영향이 없다. 1항 "서비스 이용 중 입력·생성" 범위의 화면 설정이다.

**설계와 다른 점**

1. **펼침 자리 = U1 칸 줄**(행성 아래 3칸씩) — 설계 §2.3 의 "아래쪽 반원 부채꼴"은 이름표 104px 가 이웃 위성 이름표와 겹치고 56px 간격을 못 지켜(위성 6개 계산 — 이웃 사이 55px) U1 칸 줄(회귀가 이미 상자 안·56px·원판 8px 을 지킴)을 썼다. 그래서 계 상자가 설계 계산(§1.2 — 이야기 궤도 1: 270)보다 크다: 이야기 위성 1~3 = 312 · 4~6 = 420 · 시기 160 위성 1~3 = 344. 시간 줄기가 U1 보다 위성 있는 계마다 약 56px 길어진다.
2. **패널 닫기 = 펼침 유지**(§2.3 은 재개) — 패널이 모달이라 열려 있는 동안 지도를 누를 수 없다. 닫을 때 접히면 펼친 위성(바로가기)을 누를 길이 없어, 펼침은 고르기를 따르게 했다(재개 = 다시 탭·다른 곳·Esc·[선택 풀기] — 지시 범위 그대로).
3. **전체 보기 배율 = 그 자리 멈춤**(§2.1 은 애니메이션 제거) — 다시 확대할 때 튀지 않게. 멈춘 공전은 메인 스레드를 쓰지 않는다(아래 실측 — 멈춤 0.2~0.5ms/초).
4. **키프레임 한 벌 = 4바퀴**(§2.1 은 한 바퀴) — 실측에서 반복 경계마다 브라우저가 `animationiteration` 이벤트를 보내며(React 가 뿌리에 애니메이션 이벤트 수신기를 단다) 메인 스레드가 약 75ms 동안 매 프레임 그렸다. 한 바퀴씩이면 경계가 잦아 가만히 300 노드 10~13ms/초(기준 10 초과) → 4바퀴로 경계를 4배 줄여 아래 값.
5. **이름표 지연 = 위성과 같은 값을 직접 붙임** — CSS `animation-delay: inherit`(처음 구현)은 합성기로 넘어가지 않아 메인 스레드가 매 프레임 계산했다(100 노드 가만히 47~84ms/초). 직접 붙이자 이름표 없는 경우와 같아졌다.
6. **`[움직임 멈추기]`는 `aria-pressed` 안 씀** — 이름이 바뀌는 버튼이라 눌림 상태를 겹쳐 알리지 않는다(이름 + 아이콘이 상태).
7. **안 한 것**: `[항로 보기]`(U1 보고 3 그대로 — U2 범위 밖) · 두 손가락 확대 중 프레임·1배 Chrome 전체 CPU·실기기 배터리(§2.6 ②의 확대·④·⑤ — 아래 "남은 것").

// User 에 한 줄: nodeDecorations NodeDecoration[]
model NodeDecoration {
  id        String   @id @default(cuid())
  userId    String

  nodeType  NodeType
  nodeId    String
  shape     String   // 모양 값 — 목록은 코드(lib/space-decor.ts 가칭)만, DB CHECK 없음

## 부록 B — 측정 방법(스크립트는 job 임시 폴더, 커밋 안 함)

- **운영 집계:** SQL `COUNT`·`percentile_disc` 만 반환(이름·id·본문 0). 이야기 위성 = 대상 인물(확정 사람) ∪ `EPISODE>PERSON`(확정)·`EPISODE>PERSON_GROUP` ∪ 브릿지 메모리 `MemoryPlace.placeId` — `getMyLifeData` 의 칩과 같은 정의. 시기 직접 위성 = `PersonLifeEvent` ∪ `LIFE_EVENT>PLACE`·`LIFE_EVENT>PERSON_GROUP`.
- **공전 성능:** 헤드리스 Chrome 156 + CDP(Node 22 기본 WebSocket). 정적 HTML 시제품(계 상자 360×270, 궤도 RX 150·RY 100, 키프레임 36걸음 2벌, 음수 지연으로 자리 나눔). 가만히 6초(`Performance.getMetrics` `TaskDuration` · `SystemInfo.getProcessInfo`) 잰 뒤 3초 추적(카테고리 `cc`·`benchmark`·`disabled-by-default-devtools.timeline.frame` → `PipelineReporter` 상태·시각). 끌기는 rAF 로 지도 transform 을 사인 곡선으로 움직이며 rAF 간격 기록.
  - 첫 측정에서는 측정용 rAF 고리가 늘 돌아 메인 프레임을 계속 요구했고, 그 탓에 CSS 공전이 메인 스레드를 쓰는 것처럼 보였다. 고리를 측정 중에만 돌게 고치고 합성기 프레임은 추적으로 따로 세어 다시 쟀다(앞 결과는 버림). 이 오류는 앱에서도 같다 — **화면이 가만할 때 rAF 를 계속 돌리는 코드가 있으면 CSS 공전의 이득이 사라진다**(U2 정적 검사 대상).
- **390 글자 수:** `next dev`(로컬, 운영 DB) + 픽스처 계정(`fixture-space-390@lifebook.invalid`, 앱 경로 `createPersonNode`·`createPlaceNode`·`createGroupNode`·`createStoryNode` 로 시드) + 세션 쿠키 발급(`next-auth/jwt` encode) + 헤드리스 Chrome(390×844·DPR 3·터치). TreeWalker 로 화면 안 글자 노드의 실제 위치(`getClientRects`)를 보고 셈. 사이드 패널 열림/닫힘 두 번. 끝에 계정 삭제(1건).
