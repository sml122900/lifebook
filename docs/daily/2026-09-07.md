**원인 2겹.**
1. `submitEpisodeTurn` 의 P10-3 처리가 종료 신호가 든 *메시지 전체* 를 요약
   입력에서 뺐다. "역사 수업 시간에 재밌는 이야기를 많이 해주셨어요. 그걸로
   된 것 같아요" 처럼 한 메시지에 내용+종료가 섞이면 내용까지 통째로 사라져

2. 그 상태로 요약 모델(Sonnet)을 부르면 "내용 부족" 판단 → 사용자에게 더
   말하라는 2인칭 안내문을 생성 → `finishEpisodeChat` 이 빈 문자열만 아니면
   그대로 `Episode.content` 로 저장했다.

**수정.**
- `lib/episode-text.ts` 신설(순수 모듈, 클라·서버·검증 공유) —
  `EXIT_PHRASES`/`EPISODE_DONE_PHRASES` 와 `isExitIntent`/`isEpisodeDoneIntent`
  를 ChatV3Client 에서 이곳으로 이동. `stripEpisodeDoneSignal(text)` 가 문장
  단위(마침표·물음표·느낌표·줄바꿈)로 나눠 종료 신호가 든 문장만 버리고
  내용을 돌려준다. `isSummaryGuidance(text)` 가 요약 결과의 2인칭 안내
  패턴(주세요·주시면·드리겠·습니다·정리할 내용·내용이 없·~신가요·물음표
  끝)을 판정.
- `ChatV3Client.submitEpisodeTurn` — 종료 신호 감지 시 남는 내용이 있으면
  마지막 본인 턴으로 transcript 에 넣고 마무리. `handleSend` 명시 종료
  ("그만할래요") 경로도 동일.
- `finishEpisodeChat` — (a) 본인 발화 0 이면 모델을 부르지 않고
  `저장할 이야기가 없어요` 반환("이 대화에는 실제 이야기 내용이 없어…"
  판정문 저장 차단), (b) 요약 결과가 안내문이면 거부 → 더 강한 지시를 붙여

  안내문은 content 에 못 들어간다.
- `EPISODE_SUMMARY_SYSTEM_PROMPT` — "절대 사용자에게 말 걸지 말 것", "입력이
  한 문장이어도 -다체 서술로 정리" + 예시 2개(핸드오프 사례 그대로).
- `finishEpisodeStage` — 본인 턴 0 이면 `saveEpisode` 를 안 타고(“저장하지
  못했어요” 노출 방지) 컨텍스트만 비운 뒤 "다른 이야기도 있으세요?".

## P15-1. 마무리 멘트 순환 안 됨 — 리마운트마다 ref 리셋

  하나마다 달랐다(0e575f2e → 2896c0f1 → 5e9afa0f → a73e1c07 → b48eeab9).
  사용자는 이야기마다 /chat-v3 를 새로 들어왔고, P14-4 의 `closingIdxRef`
  (useRef) 는 마운트마다 0 → 항상 첫 문구. 내용 반영형 1회는 모델 마무리
  (P12-7 afterModelClosing 경로)였음 — 추정대로 시스템 4종은 사실상 안 돌았다.

  `nextClosingIndexFromLog(loaded)` 추가 — `init()` 이 복원한 로그에서 마지막
  으로 쓴 마무리 문구를 찾아 그 다음 인덱스부터 잇는다. 저장소(localStorage
  등) 추가 0, 로그가 DB 에 있으니 리마운트·새 기기에서도 이어진다.

## P15-2. 에피소드가 엉뚱한 앵커에 귀속 — dedup 아님, stale pending

- 실제 시퀀스(UTC): 12:49:38 국민학교 person 갭 → "김영수" → 김영수 에피소드
  오프닝 → 12:49:48 **"이제 그만할래요"(본인 턴 0)** → 세션 종료. 이 exit
  경로는 본인 턴이 있을 때만 `clearPending()` 을 불렀으므로
  `ChatV3PendingContext(EPISODE, 국민학교, 김영수)` 가 남았다.
- 12:50:51 새 세션 진입 → `tryResumePendingContext` 가 그 컨텍스트를 **소리
  없이 이어받음**(봇 재질문 없음) → 사용자가 자유롭게 친 "고등학교 다닐 때
  이야기를 하고 싶어요" → "국사 선생님 박정호…" 가 김영수·국민학교 에피소드
  턴으로 흡수 → `Episode(lifeEventId=국민학교, personId=김영수)` 로 저장.
  DB 도 그대로: 국민학교 Episode content "고등학교 시절, 국사 선생님이셨던
  박정호 선생님이 기억난다", personId=김영수. 고등학교 이벤트는
  `personAsked=false`·people 0 — 고등학교 person 갭은 애초에 실행된 적이
  없다. `createEpisodeBridge`/dedup 은 "지금 활성 갭 이벤트"에 정확히 붙였다
  — 활성 갭 자체가 잔재였던 것.
- 수정 2겹:
  1. `handleSend` 명시 종료 — stage 가 episode/person 이면 저장 여부와 무관
     하게 `clearPending()`. "다음에 오시면 이어서 여쭤볼게요"는 갭 카드로
     다시 묻는다는 뜻이지 컨텍스트를 몰래 이어간다는 뜻이 아니다.
  2. `tryResumePendingContext` — 마지막 봇 발화가 `SESSION_END_MESSAGES` 면
