# 토큰 충전 — 토스 심사(포인트충전 업종) 준비 (2026-11-10)

토스가 Lifebook 을 **포인트충전 업종**으로 분류 → 이번 심사에 토큰 충전도 포함(성민 지시 2026-11-10). 카드사 심사는 아직 시작 전.
문구는 전부 [임시 — 성민 확정 필요] · [법률 검토 필요].

## 1. 상품(서버 진실 = `lib/tokens/policy.ts` `TOPUP_PACKAGES`)

| id | 결제 금액 | 받는 토큰 | 그중 더 드리는 토큰 |
|---|---|---|---|
| starter | 1,000원 | 100 | 0 |
| value | 3,000원 | 330 | 30 |
| popular | 5,000원 | 575 | 75 |
| max | 10,000원 | 1,250 | 250 |

기준 1,000원 = 100토큰. 무료 지급: 가입 50(`signup_grant`) · 출석 매일 5(`daily_attendance`) · 7일 연속마다 +30(`attendance_streak_bonus`). 차감을 되돌린 것(`*_refund` — 검색 실패 등)은 꺼낸 칸으로 돌아감.

토스 공개 안내(카드사 심사 체크리스트, 2026-10-06): 충전 서비스는 **1일 최대 결제 금액 5만 원 미만**(카드사 정책). → **서버 하루 한도 49,999원**(2026-11-10 성민 — `TOPUP_DAILY_LIMIT_KRW`): 사용자당 그날(한국 시간) 결제된 충전 합계 + 이번 금액이 넘으면 대기 주문을 만들 때와 결제 승인 전 두 번 거절. 충전 화면에 "오늘 남은 한도" 안내 · 넘는 상품은 고를 수 없음 · `/shop/tokens` 에 "하루에 49,999원까지"(문구 [임시]).

## 2. 경로

- 상품 소개(로그인 없이): 상점 `/shop` [토큰 충전] → `/shop/tokens`(금액·토큰·환불과 쓰는 곳) → [충전하러 가기]
- 충전(로그인): `/billing` — 충전할 토큰 고르기 → 토스 결제위젯 v2(인쇄본과 같은 위젯 키 — 결제 수단·약관) → [N원 충전하기] → 결제창 → `/billing/success`(서버가 위젯 시크릿 키로 승인 + 주문 금액과 대조 → 즉시 적립)
- 다른 입구: 로그인 전 메인(`/`) 상품 칸 — 토큰 카드 [토큰 충전 보러 가기] → `/shop/tokens` · [상점 전체 보기] → `/shop`(2026-11-10 2차, 문구 [임시]) · [내 정보] → [상품 구매] → 상점 · [내 정보] → 토큰 화면 → [토큰 충전하러 가기] · 토큰이 부족할 때 안내

## 3. 환불(문장 한 곳 = `lib/commerce/order-display.ts` `TOKEN_REFUND_LINES`)

같은 문장: 환불정책 `/refund` 토큰 충전 절(v1.2) · 이용약관 제25조(v1.2) · 충전 화면 · 상점 토큰 상세 · 고객센터 "토큰 환불이 되나요?". 옛 "충전한 토큰은 환불이 어렵습니다" 지움.

- 결제 후 7일 안 + 하나도 안 쓴 충전 = 결제 금액 전부
- 그 밖 = 결제 금액 × 남은 토큰 ÷ 그 충전으로 받은 토큰(더 드린 토큰 포함), 원 아래 버림
- 무료 토큰은 환불 대상 아님 · 사용 순서 = 무료 먼저 → 먼저 충전한 것부터
- 쓰는 곳 = Lifebook 서비스 한 곳, 현금·다른 서비스로 바꿀 수 없음
- 고객센터 요청 → 3영업일 안 결제 수단으로

**계산이 되는지**: 지갑은 잔액 한 칸이지만 모든 잔액 변경이 원장(`TokenTransaction`)에 이유와 함께 남음(`lib/tokens/wallet` 불변식). `lib/tokens/refund.ts` `quoteTopupRefunds` 가 원장을 처음부터 따라가 무료·충전 건별 남은 토큰을 셈. 운영 32지갑 전부 무료 + 유료 남은 = 잔액(2026-11-10 `db/token-refund-quote.ts --all`, 읽기만). 건별 금액 = `--email <이메일>`.

**환산 확정**(2026-11-10 성민): 받은 토큰(더 드린 토큰 포함) 대비 남은 유료 토큰 비례, 수수료 없음 — 문구는 [임시] 유지 · 법률 검토 목록.

**환불 실행**(2026-11-10): 사용자는 고객센터로 요청 → 운영자가 관리자 화면 `/admin/tokens`(ADMIN_EMAILS — proxy·레이아웃·액션 3중)에서 금액을 보고 금액 확인 체크 + [환불 실행] → `lib/tokens/refund-exec` `refundTopupOrder`: 주문·지갑 행 잠금 → 이미 환불했으면 거절 → 원장으로 금액 다시 계산 → 토스 결제 취소(결제 금액 전부면 전액, 아니면 부분 · Idempotency-Key 주문마다 하나 · 2026-11-10 이후 충전 = 위젯 키) → 성공했을 때만 지갑 차감 + 원장 `topup_refund`(사용자 토큰 화면 내역 "충전 환불"). 취소 실패면 원장·지갑 그대로. 주문 행은 paid 그대로(결제 기록 5년 보존).
- 회귀 `test-print` ⑫(가짜 토스 취소): 미사용 전액 · 일부 사용 비례 · 무료 토큰 제외 · 같은 충전 두 번 거절 · 취소 실패 시 원장 그대로 · 다 쓴 충전 거절.
- 실제 확인(2026-11-10, 로컬 서버 + 토스 문서 공개 테스트 키 — 우리 위젯 키는 Vercel 에만 있음): 3,000원 테스트 결제(퀵계좌이체 테스트 흐름) → 330토큰 적립 → 160 사용(무료 50 + 유료 110) → 관리자 화면 환불 → 토스 결제 조회 `PARTIAL_CANCELED`·취소 2,000원 `DONE`·남은 결제 1,000원 · 원장 "충전 환불 −220" · 잔액 0. 확인용 계정·주문·원장 지움.

## 3-1. 유효기간(2026-11-10 성민)

- **유료 토큰 = 충전일로부터 1년**(토스 기준: 무형 상품 제공 기간 1년 이내). 만료일 = 그 충전의 결제 시각 + 1년(`lib/tokens/refund` `topupExpiresAt` — 원장에서 계산, 마이그 0).
- 사용 순서 = 무료 → 만료가 가까운 충전(유효기간이 모두 같아 먼저 충전한 것부터와 같음).
- 만료 30일 전부터 토큰 화면(`/account/tokens`)에 "곧 기간이 끝나는 충전 토큰이 있어요 — N토큰, ○년 ○월 ○일까지" 표시. 알림 발송 없음. 문구 [임시].
- 문장 "충전한 토큰은 충전일로부터 1년 동안 쓰실 수 있어요." — `TOKEN_REFUND_LINES` 한 곳 → 환불정책(v1.3)·약관 제25조(v1.3)·충전 화면·상품 화면·고객센터. [임시]
- **만료된 유료 토큰 처리(소멸 vs 환불) = 법률 검토 목록.** 결정 전에는 지갑에서 빼지 않고, 자동 환불도 하지 않음(관리자 화면 "만료 — 처리 방식 법률 검토 중", `refundTopupOrder` → `expired`). 지금 가장 오래된 충전(2026-06, 성민 테스트 결제)도 2027-06 만료라 당장 생기는 경우는 없음.
