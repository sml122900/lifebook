# auth() 요청 단위 재사용 (2026-11-05)

> 결정: 성민(2026-11-05 지시) · 구현·측정: Claude Code

## Problem

- `auth()`(Auth.js v5, `auth.ts` Node 인스턴스)를 부를 때마다 jwt 콜백이 DB 를 두 번 읽는다 — 동의 상태(`User` 동의 칸·버전)와 옛 사용자 지갑 보정(`ensureWalletWithSignupGrant`).
- 이유(그대로 둠): Edge 미들웨어(`proxy.ts`)는 Prisma 를 못 쓰므로, Node 쪽이 세션을 다룰 때마다 DB 의 최신 동의 상태를 토큰에 실어 두고 미들웨어는 쿠키만 보고 `/consent` 로 보낼지 정한다(동의 버전이 올라가면 재동의 · 다른 기기에서 동의하면 쿠키 갱신).
- 그런데 서버 컴포넌트 한 번 그리기 안에서 레이아웃·페이지·위젯이 각각 `auth()` 를 불러, 같은 요청에서 같은 조회를 여러 번 했다. 측정(서버 지연 조사, 2026-11-05): My Life 첫 화면 3회 · 이야기 글 저장(액션 + 같은 응답의 다시 그리기) 4회.

## Action

- `auth.ts`: NextAuth 인스턴스의 `auth` 를 `authEveryCall` 로 받고 `export const auth = cache(authEveryCall)`(React `cache`). `handlers`·`signIn`·`signOut` 은 같은 인스턴스 그대로.
- 기억 범위 = 서버 컴포넌트 그리기 요청 하나. 그 요청에서 처음 한 번은 jwt 콜백이 DB 를 읽으므로, 그 요청이 보는 동의 상태는 바꾸기 전과 같다. 세션 갱신(`/api/auth/session` — 동의 직후 `update()`, `ConsentSessionSync`)은 `handlers` 가 처리해 이 기억과 무관하다.
- 앱의 `auth()` 호출은 전부 인자 없이(129곳 import, 인자 있는 호출 0 — `test-auth` ④ 가 지킴). `proxy.ts` 무접촉(auth.config 로 만든 Edge 인스턴스).
- 바꾸면 안 되는 이유는 찾지 못했다 — jwt 콜백이 DB 를 읽는 목적(토큰을 최신으로)은 요청마다 한 번이면 충족된다.

## Result

**전후 비교** — 운영 빌드(`next build` + `next start`, 이 PC) · 픽스처 계정 · 브라우저 없이 문서 요청만(하이드레이션 뒤 클라이언트 세션 조회가 섞이지 않게) · 3회씩 · DB 왕복 = `pg` 왕복 기록(앱 코드 무수정, 미리 불러 씀). 이 PC ↔ Supabase(서울) 왕복 1회 ≈ 68ms.

|---|---|---|
| My Life(`/my-life`) | 39 · 3 · 592~610ms | 34 · 1 · 445~448ms |
| 이야기(`/my-life/story/[id]`) | 36 · 3 · 577~590ms | 31 · 1 · 439~450ms |
| 글 고치기(`…/edit`) | 23 · 3 · 588~597ms | 18 · 1 · 441~445ms |
| 이야기 글 저장(브라우저 — 액션 + 같은 응답의 다시 그리기) | 57 · jwt 조회 11 · 액션 첫 바이트 901~921ms · 끝 1.64~1.86초 | 52 · 7 · 904~921ms · 1.64~1.75초 |

- 화면마다 `auth()` 3회 → 1회(DB 왕복 −5). 이 PC 에선 첫 바이트 약 −145ms. 운영(Vercel 함수 서울 icn1 · DB 서울 — 같은 리전이라 왕복당 수 ms 추정)에선 차이가 작다.
- 글 저장 액션의 첫 바이트는 그대로 — 액션 안 `auth()` 는 1회 그대로이고(액션 단계는 기억하지 않음), 줄어든 것은 같은 응답의 다시 그리기 쪽.

**동의 흐름(브라우저 실측, 전후 같음)** — 픽스처 동의 칸만 바꿔 확인:
- 게이트: 쿠키 동의 버전 3 → `/my-life` → `/consent`(폼) ✅
- 동의 직후 세션 갱신: 폼 제출 → DB 버전 4 · 쿠키 버전 4 · `/enter` → `/my-life` ✅(화면 뜨고 3초 뒤 · 0.3초 뒤 두 경우)
- 쿠키만 옛 값(DB 4 · 쿠키 3): `/my-life` → `/consent` 1회 → 세션 다시 받음(쿠키 4) → `/enter` → `/my-life` ✅
- `/enter` 바로 → `/my-life` ✅

**곁들여 본 것(바꾸기 전 코드, 이번 변경과 무관)**: 화면이 뜨고 약 0.3초 안에(세션 첫 조회가 끝나기 전) 동의 폼을 제출하면 `update()` 가 아무것도 안 하고 끝나 쿠키가 옛 값으로 남고 `/consent` 에 머문 적이 1번 있었다(DB 는 4). 다시 돌렸을 땐 재현되지 않았다. 사람이 체크 3개를 누르는 데 걸리는 시간으로는 생기기 어렵다 — 관찰만 기록.
